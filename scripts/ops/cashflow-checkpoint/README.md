# Cash-flow encrypted backup checkpoint

This directory owns the wrapper, .NET crypto helper, synthetic tests and receipts only. No live SSH/backup/database operation has run during implementation. Independent review found no P1/P2 issue; the subsequent fail-closed preloaded-type guard passed the 16-check offline suite. The tested wrapper and crypto hashes are recorded in `offline-receipt-20261020.json`. Before live Capture, the coordinator must verify those exact code hashes and the release preflight. This is an operator review gate under existing authorization, not a new user permission request. `.gitattributes` preserves the tested source bytes; synthetic fixtures, keys and ciphertext are excluded from Git.

`backup-checkpoint.ps1` requires PowerShell 7 on Windows and a **fresh `pwsh -NoProfile -File` process for each Capture and Verify**. It fails closed if either helper class is already loaded; it never reuses a potentially foreign class from an interactive session. It **does not start a backup**. It captures exactly seven files from one completed native backup/restore directory, verifies receipt success and source/archive hashes, and checks current source identity/health and stopped isolated target metadata. The reviewed native helper must be staged byte-identically at `/root/portfolio-recovery-tools/cashflow-native-reviewed.py`; its SHA256 is pinned to `2c07a483ef318a3b381e4b832b0de9a5c3fc874a69d131af2f515e475b84c30b`. Use binary transfer such as existing SSH `scp` for staging; do not pipe through `Get-Content`, `Set-Content`, text decoding, or newline conversion. Recompute the local and remote SHA256 against the reviewed bytes before executing the helper. Native backup execution must use `/root/portfolio-recovery-backups/.cashflow-release.lock`; Capture takes a nonblocking shared lock during metadata inspection and refuses an active exclusive backup writer.

Exact allowlist, confirmed from native source: `postgres.dump`, `globals.private.sql`, `cron.private.json`, `source-inventory.private`, `target-inventory.private`, `comparison.private.json`, `receipt.json`. Private errors and `target.private.env` are excluded. No secret, row, plaintext archive or recovered key is printed. The local manifest contains filenames, hashes and lengths only; the original native receipt is encrypted. Source raw files remain private remotely; the wrapper does not delete or overwrite them.

Live destination is fixed to `C:/Users/Asus/.codex/private/cashflow-release/<CheckpointId>`. The wrapper refuses existing Capture destinations, reparse points and unreviewed helper hashes. It creates a protected directory ACL for the current SID and SYSTEM only, then CreateNew files. It requires estimated ciphertext size plus 1GiB free locally. Verify requires the same protected directory ACL. SSH uses the existing fixed key/host, strict host key checking, batch mode, 15-second connection timeout and process-tree kill deadlines (180 seconds metadata; 900 seconds per file). Binary stdout goes directly to crypto, never through PowerShell's text pipeline. SSH stderr is discarded; failures emit only constant stage/code and exit nonzero. Partial output is preserved; no automatic retry, cleanup, additional backup or restore occurs.

Encryption uses .NET AES-256-CBC/PKCS7 with a fresh random IV per file and independent HMAC-SHA256 key (encrypt then MAC). A random 64-byte AES/HMAC master is wrapped with Windows DPAPI CurrentUser and fixed domain entropy. Each file authenticates magic/version, header length, exact UTF-8 context/source hash/length header, IV and ciphertext. The final 32 bytes are the MAC. The manifest's exact bytes have a separate HMAC. File hashes are additionally bound inside that authenticated manifest. Verify authenticates the entire ciphertext with an exclusive file handle before decrypting on the same handle, then hashes all decrypted bytes with a 64KiB buffer. No plaintext file is produced. Master/key/buffer arrays are cleared where owned by this code; this is not a claim that all managed-runtime copies can be erased.

DPAPI recovery requires this Windows identity/profile. This tool has no Restore/export mode and is not portable off-device disaster recovery. Live Capture is eligible only after the native helper has successfully restored that release's original archive on isolated PG; Verify then establishes that decrypted bytes exactly match the same source archive and auxiliary files. It does not start a second PG restore, validate storage blobs, prove every row's contents, or refresh the database. No fresh live checkpoint has been captured or verified by this package.

After root review and a separately completed successful native backup/restore, use the actual native receipt timestamp (not a new invented ID):

```powershell
$id = '<actual YYYYMMDDTHHMMSSZ from native receipt>'
$dest = "C:/Users/Asus/.codex/private/cashflow-release/$id"
$pin = '2c07a483ef318a3b381e4b832b0de9a5c3fc874a69d131af2f515e475b84c30b'
pwsh -NoProfile -File './backup-checkpoint.ps1' -Action Capture -CheckpointId $id -ReviewedHelperSha256 $pin -Destination $dest
if ($LASTEXITCODE -ne 0) { throw 'Checkpoint capture failed; preserve partial output and inspect stage only' }
pwsh -NoProfile -File './backup-checkpoint.ps1' -Action Verify -CheckpointId $id -ReviewedHelperSha256 $pin -Destination $dest
if ($LASTEXITCODE -ne 0) { throw 'Checkpoint verification failed; do not install from an unverified checkpoint' }
```

Run from this directory; no live command has been executed here. `capture-complete.json` explicitly says `CAPTURED_NOT_VERIFIED`; only a successful Verify creates `verified.json`. Existing verification receipts are never overwritten. A failed later invocation does not invalidate or refresh an older receipt automatically; the caller must inspect the current exit status and matching manifest hash. Before installation root still refreshes the release-specific operational preflight.

Offline checks: `pwsh -NoProfile -File ./offline-tests.ps1`. Fixture mode is restricted to this directory's `test-output` subtree and requires a synthetic marker. All fixtures are synthetic. Each run uses a new owned path and retains evidence, including rejected/tampered copies. No fixture path can select SSH or the private live destination. Synthetic coverage includes seven-file roundtrip, three buffer crossings, empty source, header/cipher/tag corruption at the crypto boundary and wrapper boundary, wrong master, missing ciphertext, manifest tampering, existing-destination preservation, unreviewed pin, and bad source proof. The timestamped `offline-receipt-*.json` pins the code tested.
