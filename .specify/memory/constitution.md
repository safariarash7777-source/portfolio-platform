# Project constitution — Spec Kit adoption pilot

Version: 1.0.0 · Adopted: 2026-11-03

This is a project-authored specification workflow pilot, not evidence of an installed Specify CLI or agent integration. Existing repository instructions and explicit owner decisions govern.

1. Read docs/README.md first. Product direction belongs to PRODUCT-BLUEPRINT, decisions to DECISION-LOG, live status exclusively to COMMAND-CENTER. Link these documents; do not duplicate their state.
2. Preserve Arash's canonical identity: آرش صفری — تحلیلگر و مشاور سرمایه‌گذاری. Preserve the approved RTL design and financial/access contracts.
3. Inspect current main and delivery receipts before planning. Reuse completed implementations. A historical blocker must be rechecked before treating it as current.
4. Define user-visible outcomes, acceptance evidence and explicit exclusions before implementation. Tasks name owners, dependencies and verification; task completion is not inferred from a commit.
5. Financial facts retain source, date, period, definition and unit. Unknown stays unknown/null. Separate facts, inference and scenarios. Private research approval does not authorize public advice or trading.
6. Respect current file/runtime ownership. Shared changes require coordinator integration. No parallel edits to another owner's scheduler, ledger or locks.
7. Code, CI, Preview, database installation, runtime execution and user acceptance are separate claims. Record exact evidence in existing receipt locations and let the COMMAND-CENTER owner update status.
8. Reuse prior valid tests; rerun affected checks when code or evidence changes. Preserve user history and reconcile unknown writes before retrying.

Amendments require an explicit rationale linked to the existing decision log; this file cannot silently override product policy.
