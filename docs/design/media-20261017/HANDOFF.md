# رسانهٔ آرش — سه چیدمان قابل تعویض

۱۷ اکتبر ۲۰۲۶. انتخاب مستقیم آرش: هر سه طرح حفظ شوند و مدیر بتواند هرکدام را بالا بیاورد. این بسته Preview opt-in است؛ هنوز انتخاب سراسری همهٔ بازدیدکنندگان را فعال نمی‌کند.

## اجرا و مسیرها

- `/design/media#layout=1`، `#layout=2`، `#layout=3`: نمونهٔ مستقل با اسنپ‌شات ۱۲ محتوای عمومی موجود، بدون تماس با API دریافت شبکه‌ها.
- `/insights?mediaPreview=1`: همان reader موجود و همان فیلترهای DB/RLS، با کامپوننت جدید. مسیر پیش‌فرض `/insights` تغییر ظاهری ندارد.
- `/admin/content`: بخش «ظاهر رسانه» به همان ContentHubManager اضافه شده؛ هر سه طرح و انتخاب کاور را در Preview تنظیم می‌کند. guard مدیریت موجود تغییر نکرد.

شاخه: `codex/arash-media-three-layouts-20261017`؛ پایه: `e4c14012f0cf106fe52b51ecd25351cc3b2ce139`. مخزن موجود استفاده شده و backend موازی ساخته نشده است. بستهٔ سه میز قدیمی با این کار مخلوط نشده.

## رفتار ساخته‌شده

مجله، مطالعه و گالری روی یک قرارداد محتوای موجود کار می‌کنند. فیلتر شبکه/نوع فقط از دادهٔ موجود ساخته می‌شود. جست‌وجو و فیلتر در hash URL حفظ می‌شوند. جزئیات با dialog، بستن/Escape، بازگرداندن focus و scroll باز می‌شوند؛ متن و لینک اصل در دسترس می‌ماند. لینک‌ها فقط https و میزبان شناخته‌شده‌اند؛ HTML جاسازی‌شده رندر نمی‌شود. URL خصوصی شناخته‌شدهٔ Telegram و میزبان جعلی رد می‌شوند. تکرار URL فقط هنگام نمایش کنار گذاشته می‌شود و رکوردی حذف نمی‌شود.

انتخاب پیش‌فرض، حالت کاور و حداکثر سه شناسهٔ منتخب در کلید `arash.media.preview.v1` مرورگر ذخیره می‌شوند. این تنظیمات حساب کاربری یا سطح دسترسی نیستند. انتخابگر بالای صفحه برای مرور هر سه نماست؛ کنترل مدیریت برای ثبت پیش‌فرض نمونه است. در گام سراسری، کنترل عمومی مدیریت نمونه باید از UI عمومی حذف شود و تنها پنل محافظت‌شدهٔ موجود نویسنده باشد.

## کاورها و مرز اتصال

سه فایل هنری جدید در `public/media-preview/` با ImageGen ساخته و به WebP تبدیل شده‌اند: debt، podcast، world. تصاویر در Preview صریحاً «کاور هنری نمایشی» هستند و برای چند پست استفاده می‌شوند؛ هنوز برای هر پست یک تصویر منحصربه‌فرد خودکار ساخته نمی‌شود. متن‌ها از صفحهٔ عمومی موجود در ۲۵ مهر ثبت شده‌اند؛ عنوان/کپشن جدید به جای متن واقعی جعل نشده است. تاریخ سابقه با برچسب «تاریخ ثبت‌شده» می‌آید و زمان منبع/همگام‌سازی تا داشتن شاهد «تأیید نشده» است.

گزینهٔ «فقط تصویر اصلی منبع» اکنون fallback صادقانه نشان می‌دهد؛ schema فعلی URL کاور یا فایل رسانه ندارد. صوت/آلبوم/پخش مستقیم در این بسته ادعای فعال بودن ندارد. رسانهٔ ناموجود لینک اصل را حفظ می‌کند. YouTube/topic تا داشتن قرارداد واقعی غیرفعال‌اند. استوری فقط اگر دادهٔ معتبر موجود باشد در نوع‌ها ظاهر می‌شود؛ آرشیو استوری یا محتوای منقضی ساخته نمی‌شود.

برای کاور آینده ایجنت دائماً روشن لازم نیست: ورود/تغییر محتوای عمومی → بررسی تصویر منبع و حق دسترسی → در نبود تصویر، job ساخت کاور با کلید content-id/hash/style-version → بازبینی مدیر → ثبت دارایی و منشأ. retry نباید تصویر تکراری یا هزینهٔ بی‌حد بسازد. پست خصوصی/اعضایی وارد صف عمومی نمی‌شود؛ متن خام چت/سکرت به مولد نمی‌رود. این صرفاً قرارداد پیشنهادی است؛ worker، زمان‌بند، حساب تازه، API پولی یا انتشار خودکار نصب نشده.

## گام بعدِ تنظیم سراسری — delta برای بازبینی هماهنگ‌کننده

قرارداد عمومی آمادهٔ site_settings/app_settings در جست‌وجوی محدود پیدا نشد. بدون ساخت backend موازی، یک کلید محدود `media_layout` با مقدار 1/2/3 پیشنهاد می‌شود. خواندن عمومی فقط همین مقدار؛ نوشتن فقط پس از احراز مدیر از نقش معتبر DB؛ ورودی‌های دیگر رد؛ audit تغییر و رفتار خطای ذخیره لازم است. جدول عمومی تنظیمات با رکوردهای ناشناخته به بازدیدکننده داده نشود. پیش‌فرض امن 1 و ذخیرهٔ پایدار معتبر مرجع باشد. تغییر schema/API در این commit وجود ندارد و قبل از فعال‌سازی باید جدا بازبینی، migration و آزمون anon/member/admin و جعل نقش انجام شود. pin و منبع کاور delta جدا هستند، نه فیلدهای حدسی این کلید.

## بررسی و حدود اثبات

- `next build`: موفق، مسیر `/design/media` static و حدود 122 KB first-load JS.
- TypeScript: موفق؛ targeted ESLint با صفر warning؛ diff check پاک.
- سه آزمون presentation: whitelist ترجیحات، رد لینک‌های مخرب/خصوصی شناخته‌شده، حذف تکرار نمایشی بدون تغییر ورودی.
- مرورگر: تعویض هر سه طرح، ذخیرهٔ مدیریت و reload، فیلتر/جست‌وجو، جزئیات و focus، منتخب نمونه، source-only fallback، چهار حالت داده و موبایل بدون overflow موفق.
- تصاویر و مقایسه‌ها در همین پوشه؛ نتیجهٔ بصری در `design-qa.md` ریشه.

build و اجرای محلی بدون credential واقعی انجام شد. ورود مدیر واقعی، persistence سمت سرور، دریافت زندهٔ opt-in و ACL زنده در این نوبت اثبات نشدند. اتصال سالم موجود بازسازی یا sync اجباری نشد. Production و Navbar/layout/globals/Auth/payment/schema/API مشترک تغییر نکردند.

اجرای محلی: از ریشهٔ این worktree، `npm run dev -- --hostname 127.0.0.1 --port 4190`. وابستگی‌ها برای بررسی محلی از junction به نصب موجود خوانده شدند؛ در CI نصب از package-lock اصلی پروژه انجام می‌شود. فایل env واقعی به این worktree کپی نشده است.
