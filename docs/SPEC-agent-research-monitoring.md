# مشخصاتِ Agent شمارهٔ ۱ — رصدِ رخداد و پژوهش

## اجرای واقعی محدود و عملیات — ۲۰۲۶-۱۰-۱۷

این بخش جای وضعیت آزمایشیِ تاریخیِ زیر را می‌گیرد. مالک اتصال داده، ذخیره و زمان‌بندی را صریحاً مجاز کرد. نخستین draft واقعی در دیتابیس ثبت شده و اجرای Windows Task Scheduler با provider اشتراکی Hermes آزموده شده است. PR #245 ادغام و پنل در نسخهٔ اصلی `955490f` منتشر شد؛ پذیرش مرورگر به ورود دوبارهٔ مالک نیاز دارد.

- ورودی: حداکثر هشت ناشرِ اخیراً واردشده به مخزن کدال، تا چهارصد گزارش برای هر ناشر. رسیدن به حدِ برش موجب حذف ناشر از این اجرا می‌شود، نه انتخاب مخفیانه از تاریخچهٔ ناقص. این دامنه، غربال کل بازار نیست. نسخهٔ canonical قبل از اعتبارسنجی انتخاب می‌شود؛ واحد، حساب حسابرسی، محدودهٔ شرکت اصلی، سازگاری حسابی و تاریخ گزارش کنترل می‌شود. دادهٔ نامعتبر به نسخهٔ قدیمی عقب‌گرد نمی‌کند.
- تازگی: دوره و انتشار گزارش حداکثر دویست‌وچهل روز؛ این حد برای صورت مالی است و برای قیمت لحظه‌ای مناسب نیست. زمان واقعی انتشار از فیلد رسمی یا دادهٔ خام همان اطلاعیه می‌آید؛ زمان دریافت جای آن نمی‌نشیند. فعالیت ثبت‌شدهٔ گردآورنده باید کمتر از سه ساعت باشد؛ این شاهدِ فعالیت است، نه اثبات کامل‌بودن همهٔ منابع. نخستین ورودی‌های واقعی آخرین دریافت سیزدهم اکتبر داشتند و فعالیت گردآورنده هفدهم اکتبر بود.
- پردازش: `computeRatios` و سپس `qualitativeMask`؛ فقط باندها و E-alias به مدل می‌روند. Hermes در safe-mode بدون ابزار/افزونه و با حداکثر یک turn و زمان محدود اجرا می‌شود. مدل فعلی luna است؛ انتخاب مدل پژوهش عمیق پس از ارزیابی کیفیت انجام می‌شود. API پرداختی و fallback جدید وجود ندارد.
- ماندگاری: hash ورودی و نسخهٔ قرارداد، intent قبل از فراخوانی، ذخیرهٔ محلی پاسخ معتبر قبل از ارسال، digest یکتا در دیتابیس. نتیجهٔ ارسال نامعلوم با find همان digest بازیابی می‌شود؛ ارسال مجدد پاسخ آماده، مدل را دوباره صدا نمی‌زند. حداکثر چهار ورودی تازه در روز UTC و سقف دفاعی بیست‌وچهار ثبت روزانه. قفل محلی و IgnoreNew جلوی هم‌پوشانی را می‌گیرند.
- زمان‌بند: `Portfolio-Research-Hermes` در Windows Task Scheduler، ساعتی و هنگام ورود مالک، StartWhenAvailable، سقف هشت دقیقه؛ اجرای مستقیم Node بدون تغییر execution policy. خاموشی، اینترنت قطع یا نبود نشست کاربر به معنی عدم اجراست. احراز اشتراک موجود Hermes حفظ شده؛ هیچ توکن OpenAI به سایت/VPS داده نشده است.
- دسترسی: کلید محلی اختصاصی در `%LOCALAPPDATA%/PortfolioResearch` با ACL مالک و SYSTEM؛ `IdentitiesOnly` و `IdentityAgent=none` و عدم خواندن SSH config. سرور فقط `research-bridge.py` ثابت با `restrict` اجرا می‌کند؛ stdin فقط read/find/append با قالب محدود است، نه shell یا SQL دلخواه. نقش DB به جدول جدید محدود است. پنل از نشست مدیر و RLS استفاده می‌کند؛ انتشار و تغییر پرتفوی/پرداخت/کاربر در این مسیر وجود ندارد.
- پایش/بازیابی: `last-run.json` و `state.json` خصوصی محل نتیجه و دفتر intent هستند؛ Task Scheduler exit صفر همراه وضعیت stored/unchanged شاهد موفقیت است. برای قفل رهاشده ابتدا task را Disable کنید، PID و نبود worker را احراز کنید و وضعیت started/ready را بررسی کنید. قفل خالی یا PID مرده خودکار حذف نمی‌شود؛ outcome نامعلوم یا خروجی ردشده نیازمند بررسی است. state را پاک نکنید؛ پاسخ ready باید با همان digest بازفرستاده شود. پس از اصلاح علت، اجرای محدود را اثبات و task را Enable کنید.
- توقف/بازگشت: Disable-ScheduledTask همین نام؛ در نیاز به قطع دسترسی، فقط خط کلید `portfolio-research-20261017` در authorized_keys را بردارید و INSERT نقش research_agent_writer روی جدول را revoke کنید. تاریخچه را DROP/DELETE نکنید. UI قبلی قابل بازگردانی است؛ جداول قدیمی، jobs قبلی و credentialهای قبلی نباید تغییر کنند.

پذیرش کیفیت بلندمدت، انتقال به میزبان همیشه‌روشن، هشدارهای عملیاتی، پوشش همهٔ صنایع/بورس کالا/طلا/ارز، مدل قوی‌تر و یادگیری کنترل‌شده هنوز مرحلهٔ بعدی‌اند؛ وجود یک draft این موارد را ثابت نمی‌کند.

## مسیر اول اجرا: اشتراک مالک در Hermes — ۲۰۲۶-۱۰-۱۷

درخواست جدید مالک استفاده از ظرفیت همین اشتراک است. مسیر انتخابی برای پژوهش داخلی، Hermes نصب‌شدهٔ محلی با `openai-codex` است. آزمون اتصال موفق بود و دفتر اجرای پژوهش، `subscription_included` و صفر فراخوانی ابزار ثبت کرد. API key قبلی حذف یا منتقل نشده؛ Agents API پرداختی فعلاً مسیر اول نیست. این شاهد، محدودیت روزانه/هفتگی اشتراک یا اجرای بی‌وقفهٔ دائمی را اثبات نمی‌کند.

معماری: موتور قطعی سایت → بستهٔ کیفی و شناسهٔ شاهد → worker شخصی Hermes → اعتبارسنجی سخت → پیش‌نویس برای مالک. گذرواژه یا توکن اشتراک به سایت، مرورگر کاربران یا prompt منتقل نمی‌شود. در شروع پردازش محلی به روشن و متصل بودن دستگاه وابسته است؛ استقرار روی VM شخصی نیازمند بررسی مستقل eligibility، نگهداری امن ورود و آزمون عملیات است. نسخهٔ وب عمومی و پاسخ‌گوی مشتریان از این آزمون محلی مجوز نمی‌گیرند.

مدل جاری نصب `gpt-6-luna` برای آزمون حفظ شد؛ مدل پژوهش عمیق بعد از مقایسهٔ کیفیت روی نمونه‌های واقعی انتخاب می‌شود. هیچ fallback پرداختی، خرید اعتبار، cron تازه یا تغییر برنامه‌های موجود انجام نشده است.

آزمون قابل تکرار: `node node_modules/tsx/dist/cli.mjs scripts/agents/hermes-research.ts --synthetic`. فقط ورودی ساختگی، یک نوبت مدل و زمان محدود؛ ابزارها و افزونه‌ها خاموش، فایل موقت پاک می‌شود و فقط رسید پذیرش چاپ می‌شود. خروجی نامعتبر به draft واقعی تبدیل نمی‌شود. آزمون زنده پس از اصلاح محل ارجاع‌ها با سه claim و سه سناریو پذیرفته شد؛ تطبیق شناسهٔ حساب ChatGPT میان ورود Hermes و Codex نیز برابر بود. تست ساختگی جای پذیرش گردش واقعی سایت را نمی‌گیرد.

منابع رسمی بررسی‌شده: [OpenAI ChatGPT plan usage](https://developers.openai.com/siwc/token-sharing-open-source) برای ابزارهای واجد شرایط، و [Hermes providers](https://hermes-agent.nousresearch.com/docs/integrations/providers) برای اتصال اشتراکی. برنامه‌های پولی/میزبانی‌شده مسیر eligibility جداگانه دارند. هیچ تضمینی دربارهٔ پوشش ابزارهای جانبی یا هزینهٔ میزبانی با اشتراک داده نمی‌شود.

## ادامهٔ اجرایی — ۲۰۲۶-۱۰-۱۷

مالک در گفتگو ساخت و فعال‌سازی ایجنت‌ها و استفاده از OpenAI را درخواست کرده است؛ بنابراین آماده‌سازی اجرایی اکنون مجاز است. بنر تاریخی زیر دربارهٔ «هیچ کد/کلید» وضعیت امروز نیست. این مجوز، شاهد PASS شدن تمرین ده‌روزه، مجوز انتشار خودکار تحلیل یا پذیرش کیفیت نیست.

**وضعیت فعلی: FOUNDATION_LOCAL / LIVE_EXECUTION_BLOCKED.** کلید در فایل محلیِ خارج از Git موجود است. ایجاد نشست Agents API پاسخ ۲۰۱ داد، ولی turn با `usage_limit_exceeded` شکست خورد؛ idle بودن نشست موفقیت نیست. نشست آزمایشی حذف شد (۲۰۰). هیچ دادهٔ واقعی مالی یا کاربر به آن داده نشد. پس از ورود مالک، پنل همان پروژه اعتبار صفر دلار / Free trial و Limits سطح Free tier را نشان داد. هیچ پرداخت یا تغییر سقفی انجام نشد. زمان‌بند، اتصال دادهٔ واقعی، ذخیرهٔ عملیاتی و انتشار سایت در این بسته وجود ندارند.

### مسیر کامل پژوهش بازار

۱. منابع همان مسیر ذخیره‌شدهٔ موجود سایت‌اند؛ ایجنت درخواست‌های موازی تازه به BrsApi نمی‌زند. دادهٔ تابلو، گزارش‌های ماهانه/فصلی، معاملات بورس کالا و قیمت جهانی باید هرکدام منبع، زمان، واحد، تعریف و پوشش مستقل داشته باشند.

۲. محاسبه و غربالگری در موتور قطعی موجود انجام می‌شود: مقایسهٔ دورهٔ همسان و اصلاحیه، فصل‌سازی زنجیره‌ای، حاشیهٔ سود، رشد و کیفیت جریان نقد. روند قیمت تنها با تاریخچهٔ تعدیل‌شده و کافی تفسیر می‌شود. دادهٔ بورس کالا به‌تنهایی سود شرکت را اثبات نمی‌کند؛ مقدار/نرخ، ترکیب محصول، هزینه، ارز و وقفهٔ شناسایی درآمد باید جدا شوند. نبود ورودی هر محور، همان محور را نامشخص نگه می‌دارد.

۳. بستهٔ مدل فقط باندهای `qualitativeMask` و شناسهٔ ساختگی شاهد را دارد. شناسهٔ اصلی، URL، دوره و دادهٔ عددی داخل برنامه می‌مانند. نسخهٔ فعلی فقط پنج باند بنیادی موتور را پوشش می‌دهد؛ تسلط بر تکنیکال، جریان نقد، کالا و FX هنوز پیاده یا اثبات نشده است.

۴. پاسخ مدل به ساختار محدود تبدیل می‌شود: خلاصه، FACT/INFERENCE با ارجاع، سه سناریو، شرط ابطال و محدودیت. در نسخهٔ محلی، فیلد اضافیِ انتشار، ارجاع ساختگی، متن عددی، HTML و واژگان معاملاتی رد می‌شوند. اعتبار ساختار و وجود ارجاع، صدق استدلال را ثابت نمی‌کند؛ خروجی همواره draft است.

۵. مرحلهٔ بعد اتصال draft به گردش موجود `intel_*` با هویت محدود ایجنت است. قبل از آن، وضعیت واقعی schema و RLS باید روی مقصد عملیاتی بازخوانی و هر migration با بکاپ/restore آزموده شود. هیچ service-role یا هویت ادمین در اختیار مدل قرار نمی‌گیرد.

### آموزش، حافظه و سنجش

- آموزش اولیه: دستور نسخه‌دار، تعاریف موتور، نمونه‌های تأییدشدهٔ انسانی و آزمون‌های منفی. در شروع نیازی به fine-tuning نیست.
- حافظه: منبع/زمان/هش ورودی، نسخهٔ مدل و دستور، خروجی، اصلاح انسان و دلیل رد؛ دادهٔ کاربران از حافظهٔ پژوهش عمومی جداست.
- یادگیری: بازخورد فقط مجموعهٔ ارزیابی و تغییر پیشنهادی نسخهٔ بعد را تغذیه می‌کند؛ مدل خودش دستور، دسترسی یا دادهٔ مرجع را تغییر نمی‌دهد.
- آزمون‌های مصنوعی محلی برای امنیت و قراردادند؛ جای ۵ تا ۱۰ تحلیل واقعی و سنجش پذیرش انسانی را نمی‌گیرند. نقل مستقیم در نسخهٔ فعلی تولید نمی‌شود.
- معیارهای پذیرش: نبود افشای عدد/رکورد کاربر، نبود ارجاع ناشناخته، سه سناریوی متمایز، رد ورودی کهنه/نامعتبر، توقف روی خطای بودجه، و بررسی انسانی کیفیت استدلال. پوشش واقعیت‌ها و کیفیت سناریوها جداگانه ارزیابی می‌شوند.

### اجرا و هزینه پیش از فعال‌سازی دائمی

- صف ماندگار با کلید یکتای نقش+نسخهٔ داده+نسخهٔ دستور؛ ذخیرهٔ شناسهٔ نشست/turn قبل از بازیابی نتیجه. خطای ارتباط مجوز ارسال دوبارهٔ همان کار نیست.
- در شروع هم‌زمانی یک و فقط حالت داخلی؛ تناوب هر نقش پس از مشخص شدن مصرف‌کننده و هزینهٔ واقعی تعیین می‌شود. روی دادهٔ بدون تغییر فراخوانی تازه انجام نمی‌شود.
- سقف سخت روزانه در دفتر ماندگار برنامه، سقف تعداد کار/توکن و قطع‌کنندهٔ خطای صورتحساب؛ budget نمایشی پنل به‌تنهایی سقف اجرایی برنامه محسوب نمی‌شود.
- پیش از زمان‌بندی دائمی، سقف مبلغ و مدل اجرایی باید مشخص شود. اکنون هیچ سقف مالی از طرف مالک تعیین نشده و هیچ خرید یا تغییر سقف حساب انجام نشده است.
- پذیرش عملیاتی: دریافت دادهٔ واقعی → ماسک → اجرای موفق turn → بررسی خروجی → ذخیرهٔ draft → مشاهده در پنل → اجرای دوم بدون تکرار → آزمون خاموش‌کردن. تا این زنجیره اثبات نشود وضعیت «فعال» اعلام نمی‌شود.

### کد و شواهد فعلی

`lib/intelligence/research-agent.ts` مرز ماسک، اعتبارسنجی draft و تشخیص نتیجهٔ turn را پیاده می‌کند؛ `npm run test:research-agent` آزمون‌های منفی و مثبت آن را اجرا می‌کند. این ماژول فعلاً به API یا صفحه وصل نیست. خطای واقعی آزمون حساب: `usage_limit_exceeded`؛ وضعیت پنل پس از ورود مالک: اعتبار صفر دلار، Free trial و Free tier. شش آزمون، typecheck، lint هدفمند، اسکن سکرت و build محلی PASS شدند. مرجع قرارداد API: https://developers.openai.com/api/docs/guides/agents-api/quickstart و https://developers.openai.com/api/docs/guides/agents-api/sessions .

> چه چیزی باید باشد و **از کجا می‌فهمیم کار می‌کند** — پیش از آنکه یک خط کدش
> نوشته شود.
>
> وضعیت: **`SPEC_READY`** · هیچ کدی، هیچ کلید LLMای، هیچ فراخوانیِ مدلی.

## چرا مشخصات قبل از کد

موتورِ دستی (`Gate 3`) عمداً اول ساخته شد. دلیلش این است که **تا آرش ده روز
واقعی کار نکند، نمی‌دانیم Agent باید چه کاری را سبک کند.** یک Agent که برای
گلوگاهِ اشتباه ساخته شود، سریع‌تر به جای اشتباه می‌رسد.

پس ورودیِ واقعیِ این سند، خروجیِ `intel_rehearsal_days` است: کدام مرحله وقت
می‌برد، کدام Draft بیشتر اصلاح می‌شود، کدام منبع بیشتر بی‌شاهد می‌ماند.
**تا آن داده وجود نداشته باشد، اولویتِ Agent حدس است.**

## ۱) دامنه — Agent چه کاری می‌کند

| مرحله | ورودی | خروجی | جدولِ مقصد |
|---|---|---|---|
| جمع‌آوریِ رخداد | منابعِ تأییدشدهٔ `intel_sources` | رخدادِ نامزد | `intel_events` (`status='draft'`) |
| استخراجِ شاهد | متنِ منبع + URL | نقلِ مستقیم + هش + زمانِ برداشت | `intel_evidence` |
| ساختِ Draft | رخداد + شواهد | تحلیلِ `status='draft'` | `intel_analyses` |
| پیشنهادِ سناریو | Draft | گزارهٔ `SCENARIO` با برچسبِ `base`/`upside`/`downside` | `intel_claims` |
| اتصال به سبدِ منتخب | سناریو + سبدِ مرجع | اثرِ **احتمالی** با driver | `intel_portfolio_effects` |
| ارسال برای تأیید | تحلیلِ کامل | `draft → pending_approval` | همان گذارِ موجود |

**آخرین کارِ Agent همان اولین کارِ آرش است.** Agent هرگز از
`pending_approval` جلوتر نمی‌رود.

## ۲) مرزهای سخت — و اینکه هرکدام را چه چیزی نگه می‌دارد

نوشتنِ «ممنوع» در یک سند، کافی نیست. هر مرز باید **جایی جز این سند** هم اجرا
شود:

| ممنوع | چه چیزی جلویش را می‌گیرد (نه این سند) |
|---|---|
| انتشارِ خودکار | گاردِ گذارِ `phase22`: `published` فقط از `approved_internal` می‌آید و `approved_by` لازم دارد. Agent هویتِ ادمین ندارد |
| توصیهٔ خرید و فروش | `lib/core/vocab.test.ts` — واژگانِ ممنوع در CI قرمز می‌شوند |
| تغییرِ سبد | Agent روی `intel_reference_versions` امتیازِ نوشتن ندارد؛ نسخهٔ نهایی‌شده تغییرناپذیر است |
| پیامِ خودکار به مشتری | Agent به `lib/telegram.ts` و `lib/resend.ts` دسترسی ندارد |
| تصمیمِ بدونِ شاهد | `phase22`: تحلیلی که گزارهٔ بی‌شاهد دارد به `pending_approval` نمی‌رسد |
| عددِ خامِ مالی به LLM | قاعدهٔ `qualitativeMask` در `CLAUDE.md`؛ باید تستِ اختصاصی بگیرد (بندِ ۴) |

> اگر مرزی فقط در این جدول باشد و ستونِ راستش خالی بماند، **آن مرز وجود
> ندارد**. سه ردیفِ اول امروز واقعاً اجرا می‌شوند؛ ردیفِ آخر هنوز فقط قاعده است
> و پیش از نوشتنِ Agent باید گاردِ اجرایی بگیرد.

## ۳) نقشِ دیتابیسِ Agent

Agent با **نقشِ خودش** کار می‌کند، نه با `service_role` و نه با حسابِ آرش.

```
GRANT SELECT ON intel_sources, intel_reference_* TO intel_agent;
GRANT SELECT, INSERT ON intel_events, intel_evidence, intel_claims,
                        intel_claim_evidence, intel_portfolio_effects TO intel_agent;
GRANT SELECT, INSERT, UPDATE (status) ON intel_analyses TO intel_agent;
-- هیچ DELETE، هیچ TRUNCATE، هیچ دسترسی به profiles/payments/leads
```

دو دلیل: در دفترِ گردش، کارِ Agent با کارِ آرش **قابلِ تفکیک** می‌ماند
(`actor_id` فرق می‌کند)؛ و اگر Agent خطا کند، دامنهٔ خرابی به همان جدول‌ها
محدود است. `phase23` تضمین می‌کند نقشِ تازه امتیازِ موروثی نگیرد.

## ۴) بستهٔ ارزیابی (Evaluation Harness)

Agentِ زبانی خروجیِ قطعی ندارد، پس «تست عبور کرد» معنای همیشگی‌اش را ندارد.
سنجه‌ها باید **قابلِ شمارش** باشند و مبنایشان کارِ دستیِ آرش در `Gate 3`.

### ۴-۱) مجموعهٔ سنجش

از خروجیِ ده روزِ واقعیِ `Gate 3` ساخته می‌شود: هر رخدادی که آرش دستی ثبت کرده،
با شواهد و سناریوهایش، می‌شود یک موردِ آزمون. **هیچ رخدادِ ساختگی ساخته
نمی‌شود** — اگر ده روز واقعی وجود نداشته باشد، مجموعهٔ سنجش وجود ندارد و
Gate 4 شروع نمی‌شود.

### ۴-۲) سنجه‌ها

| سنجه | تعریف | آستانهٔ پیشنهادی | چرا این عدد |
|---|---|---|---|
| **صحتِ نقلِ شاهد** | نسبتِ نقل‌هایی که واقعاً در متنِ منبع هستند | **۱۰۰٪** | نقلِ ساختگی از نبودِ شاهد بدتر است. تنها سنجه‌ای که آستانه‌اش مذاکره‌پذیر نیست |
| **دقتِ منبع** | نسبتِ رخدادها با URLِ زندهٔ قابلِ بازیابی | ≥ ۹۸٪ | ۲٪ برای لینکِ موقتاً از دسترس خارج |
| **نرخِ پذیرشِ Draft** | نسبتِ Draftهایی که آرش بدونِ بازنویسیِ اساسی تأیید می‌کند | ≥ ۶۰٪ | زیر این عدد، بازبینی از نوشتنِ دستی وقت‌گیرتر می‌شود |
| **پوششِ سناریو** | نسبتِ تحلیل‌هایی که هر سه سناریو را دارند | ۱۰۰٪ | قاعدهٔ سختِ محصول: بازه + فروض، نه عددِ واحد |
| **نرخِ خطای واژگان** | تعدادِ خروجی‌هایی با واژگانِ ممنوع | **۰** | گاردِ `vocab` قرمز می‌شود |
| **ادعای بدونِ شاهد** | تعدادِ گزاره‌های `FACT`/`INFERENCE` بدونِ شاهد | **۰** | `phase22` جلویش را می‌گیرد؛ این سنجه می‌گوید Agent چند بار **تلاش** کرده |
| **تأخیر** | از انتشارِ خبر تا آماده‌شدنِ Draft | ≤ ۳۰ دقیقه | زیرِ نیم‌ساعت هنوز برای تصمیمِ روز مفید است |

### ۴-۳) سنجه‌ای که عمداً وجود ندارد

**«دقتِ پیش‌بینی».** این محصول سامانهٔ پشتیبانِ تصمیم است، نه ربات معامله‌گر.
سنجیدنِ Agent با اینکه سناریوهایش «درست از آب درآمدند» یعنی تشویقش به
پیش‌بینیِ جسورانه — دقیقاً خلافِ کاری که باید بکند. آنچه سنجیده می‌شود
**کیفیتِ شاهد و انسجامِ استدلال** است، نه نتیجهٔ بازار.

### ۴-۴) کنترلِ شکست‌پذیری

مثلِ بقیهٔ گاردهای این ریپو، خودِ harness باید ثابت کند می‌تواند قرمز شود:
یک Draftِ عمداً معیوب (نقلِ جعلی، سناریوی ناقص، واژهٔ ممنوع) از آن عبور داده
می‌شود و **باید مردود شود**. harnessی که هرگز کسی را رد نکرده، سنجه نیست.

## ۵) پیش‌شرط‌های شروعِ Gate 4

| # | شرط | وضعیتِ امروز |
|---|---|---|
| ۱ | `Gate 3` = `PASS` با ده روزِ کاریِ واقعی | ❌ تمرین شروع نشده |
| ۲ | حداقل ۵ تا ۱۰ تحلیلِ واقعی به‌عنوانِ مجموعهٔ سنجش | ❌ صفر |
| ۳ | `intel_sources` پر از منابعِ تأییدشدهٔ آرش | ❌ خالی — تصمیمِ باز |
| ۴ | تصمیمِ مالک دربارهٔ LLM | ❌ باز |
| ۵ | `phase20`/`phase22` روی Production | ❌ `NOT_APPLIED` |

**هر پنج باز است.** `Gate 4` = `SPEC_READY`، نه بیشتر.

با MANUS هم‌پوشانی ندارد: MANUS مالکِ **تجربه** است، این بخش فقط دربارهٔ
**آمادگیِ backend** گزارش می‌دهد.

| قابلیت | Backend آماده؟ | گلوگاه |
|---|---|---|

| کارنامهٔ تحلیل‌ها | ✅ | — |
| فیدِ کدال · بانکِ داده · رصدِ بازار | ✅ | — |
| فرمِ لید | ❌ | `leads` روی Production وجود ندارد |

### Gate 6 — امنیت و پایشِ عملیاتی

| مورد | وضعیت | شاهد یا گلوگاه |
|---|---|---|
| گاردِ زبان | ✅ | `lib/core/vocab.test.ts` در CI |

### Gate 7 — رونمایی

**`NOT_AUTHORIZED`.** Cutover و رونمایی نیازمندِ تأییدِ صریحِ آرش است و در این
مأموریت هیچ بخشی از آن آماده‌سازی نشد، چون پیش‌نیازهایش (Gate 2 عملیاتی،
Gate 3 گذشته، Gate 6 بسته) هیچ‌کدام برقرار نیستند. بستهٔ Launch وقتی معنا دارد
که چیزی برای عرضه آماده باشد؛ ساختنش امروز، سندی می‌شد که هیچ‌چیز را توصیف
نمی‌کند.
