# مشخصاتِ Agent شمارهٔ ۱ — رصدِ رخداد و پژوهش

> مأموریت: `P2-CLAUDE-MEGA-004` Wave 7 · تاریخ: ۱۴۰۵/۰۵/۱۳ · `Gate 4`
>
> ⚠️ **این سند Agent نمی‌سازد.** تا وقتی `Gate 3` با ده روزِ کاریِ واقعیِ آرش
> `PASS` نشده، هیچ Agentی نوشته نمی‌شود. این سند فقط تعریف می‌کند که آن Agent
> چه چیزی باید باشد و **از کجا می‌فهمیم کار می‌کند** — پیش از آنکه یک خط کدش
> نوشته شود.
>
> وضعیت: **`SPEC_READY`** · هیچ کدی، هیچ کلید LLMای، هیچ فراخوانیِ مدلی.

---

## چرا مشخصات قبل از کد

موتورِ دستی (`Gate 3`) عمداً اول ساخته شد. دلیلش این است که **تا آرش ده روز
واقعی کار نکند، نمی‌دانیم Agent باید چه کاری را سبک کند.** یک Agent که برای
گلوگاهِ اشتباه ساخته شود، سریع‌تر به جای اشتباه می‌رسد.

پس ورودیِ واقعیِ این سند، خروجیِ `intel_rehearsal_days` است: کدام مرحله وقت
می‌برد، کدام Draft بیشتر اصلاح می‌شود، کدام منبع بیشتر بی‌شاهد می‌ماند.
**تا آن داده وجود نداشته باشد، اولویتِ Agent حدس است.**

---

## ۱) دامنه — Agent چه کاری می‌کند

| مرحله | ورودی | خروجی | جدولِ مقصد |
|---|---|---|---|
| جمع‌آوریِ رخداد | منابعِ تأییدشدهٔ `intel_sources` | رخدادِ نامزد | `intel_events` (`status='draft'`) |
| استخراجِ شاهد | متنِ منبع + URL | نقلِ مستقیم + هش + زمانِ برداشت | `intel_evidence` |
| ساختِ Draft | رخداد + شواهد | تحلیلِ `status='draft'` | `intel_analyses` |
| پیشنهادِ سناریو | Draft | گزارهٔ `SCENARIO` با برچسبِ `base`/`upside`/`downside` | `intel_claims` |
| اتصال به سبدِ منتخب | سناریو + سبدِ مرجع | اثرِ **احتمالی** با driver | `intel_portfolio_effects` |
| ارسال برای تأیید | تحلیلِ کامل | `draft → pending_approval` | همان گذارِ موجود |

**آخرین کارِ Agent همان اولین کارِ آرش است.** Agent هرگز از
`pending_approval` جلوتر نمی‌رود.

## ۲) مرزهای سخت — و اینکه هرکدام را چه چیزی نگه می‌دارد

نوشتنِ «ممنوع» در یک سند، کافی نیست. هر مرز باید **جایی جز این سند** هم اجرا
شود:

| ممنوع | چه چیزی جلویش را می‌گیرد (نه این سند) |
|---|---|
| انتشارِ خودکار | گاردِ گذارِ `phase22`: `published` فقط از `approved_internal` می‌آید و `approved_by` لازم دارد. Agent هویتِ ادمین ندارد |
| توصیهٔ خرید و فروش | `lib/core/vocab.test.ts` — واژگانِ ممنوع در CI قرمز می‌شوند |
| تغییرِ سبد | Agent روی `intel_reference_versions` امتیازِ نوشتن ندارد؛ نسخهٔ نهایی‌شده تغییرناپذیر است |
| پیامِ خودکار به مشتری | Agent به `lib/telegram.ts` و `lib/resend.ts` دسترسی ندارد |
| تصمیمِ بدونِ شاهد | `phase22`: تحلیلی که گزارهٔ بی‌شاهد دارد به `pending_approval` نمی‌رسد |
| عددِ خامِ مالی به LLM | قاعدهٔ `qualitativeMask` در `CLAUDE.md`؛ باید تستِ اختصاصی بگیرد (بندِ ۴) |

> اگر مرزی فقط در این جدول باشد و ستونِ راستش خالی بماند، **آن مرز وجود
> ندارد**. سه ردیفِ اول امروز واقعاً اجرا می‌شوند؛ ردیفِ آخر هنوز فقط قاعده است
> و پیش از نوشتنِ Agent باید گاردِ اجرایی بگیرد.

## ۳) نقشِ دیتابیسِ Agent

Agent با **نقشِ خودش** کار می‌کند، نه با `service_role` و نه با حسابِ آرش.

```
GRANT SELECT ON intel_sources, intel_reference_* TO intel_agent;
GRANT SELECT, INSERT ON intel_events, intel_evidence, intel_claims,
                        intel_claim_evidence, intel_portfolio_effects TO intel_agent;
GRANT SELECT, INSERT, UPDATE (status) ON intel_analyses TO intel_agent;
-- هیچ DELETE، هیچ TRUNCATE، هیچ دسترسی به profiles/payments/leads
```

دو دلیل: در دفترِ گردش، کارِ Agent با کارِ آرش **قابلِ تفکیک** می‌ماند
(`actor_id` فرق می‌کند)؛ و اگر Agent خطا کند، دامنهٔ خرابی به همان جدول‌ها
محدود است. `phase23` تضمین می‌کند نقشِ تازه امتیازِ موروثی نگیرد.

## ۴) بستهٔ ارزیابی (Evaluation Harness)

Agentِ زبانی خروجیِ قطعی ندارد، پس «تست عبور کرد» معنای همیشگی‌اش را ندارد.
سنجه‌ها باید **قابلِ شمارش** باشند و مبنایشان کارِ دستیِ آرش در `Gate 3`.

### ۴-۱) مجموعهٔ سنجش

از خروجیِ ده روزِ واقعیِ `Gate 3` ساخته می‌شود: هر رخدادی که آرش دستی ثبت کرده،
با شواهد و سناریوهایش، می‌شود یک موردِ آزمون. **هیچ رخدادِ ساختگی ساخته
نمی‌شود** — اگر ده روز واقعی وجود نداشته باشد، مجموعهٔ سنجش وجود ندارد و
Gate 4 شروع نمی‌شود.

### ۴-۲) سنجه‌ها

| سنجه | تعریف | آستانهٔ پیشنهادی | چرا این عدد |
|---|---|---|---|
| **صحتِ نقلِ شاهد** | نسبتِ نقل‌هایی که واقعاً در متنِ منبع هستند | **۱۰۰٪** | نقلِ ساختگی از نبودِ شاهد بدتر است. تنها سنجه‌ای که آستانه‌اش مذاکره‌پذیر نیست |
| **دقتِ منبع** | نسبتِ رخدادها با URLِ زندهٔ قابلِ بازیابی | ≥ ۹۸٪ | ۲٪ برای لینکِ موقتاً از دسترس خارج |
| **نرخِ پذیرشِ Draft** | نسبتِ Draftهایی که آرش بدونِ بازنویسیِ اساسی تأیید می‌کند | ≥ ۶۰٪ | زیر این عدد، بازبینی از نوشتنِ دستی وقت‌گیرتر می‌شود |
| **پوششِ سناریو** | نسبتِ تحلیل‌هایی که هر سه سناریو را دارند | ۱۰۰٪ | قاعدهٔ سختِ محصول: بازه + فروض، نه عددِ واحد |
| **نرخِ خطای واژگان** | تعدادِ خروجی‌هایی با واژگانِ ممنوع | **۰** | گاردِ `vocab` قرمز می‌شود |
| **ادعای بدونِ شاهد** | تعدادِ گزاره‌های `FACT`/`INFERENCE` بدونِ شاهد | **۰** | `phase22` جلویش را می‌گیرد؛ این سنجه می‌گوید Agent چند بار **تلاش** کرده |
| **تأخیر** | از انتشارِ خبر تا آماده‌شدنِ Draft | ≤ ۳۰ دقیقه | زیرِ نیم‌ساعت هنوز برای تصمیمِ روز مفید است |

### ۴-۳) سنجه‌ای که عمداً وجود ندارد

**«دقتِ پیش‌بینی».** این محصول سامانهٔ پشتیبانِ تصمیم است، نه ربات معامله‌گر.
سنجیدنِ Agent با اینکه سناریوهایش «درست از آب درآمدند» یعنی تشویقش به
پیش‌بینیِ جسورانه — دقیقاً خلافِ کاری که باید بکند. آنچه سنجیده می‌شود
**کیفیتِ شاهد و انسجامِ استدلال** است، نه نتیجهٔ بازار.

### ۴-۴) کنترلِ شکست‌پذیری

مثلِ بقیهٔ گاردهای این ریپو، خودِ harness باید ثابت کند می‌تواند قرمز شود:
یک Draftِ عمداً معیوب (نقلِ جعلی، سناریوی ناقص، واژهٔ ممنوع) از آن عبور داده
می‌شود و **باید مردود شود**. harnessی که هرگز کسی را رد نکرده، سنجه نیست.

## ۵) پیش‌شرط‌های شروعِ Gate 4

## Gate 5 · 6 · 7 — وضعیتِ آمادگی

با MANUS هم‌پوشانی ندارد: MANUS مالکِ **تجربه** است، این بخش فقط دربارهٔ
**آمادگیِ backend** گزارش می‌دهد.

| قابلیت | Backend آماده؟ | گلوگاه |
|---|---|---|
| تحلیلِ منتشرشده روی صفحهٔ عمومی | ⚠️ نیمه | سیاستِ خواندنِ عمومی (`status='published'`) از `phase20` هست، ولی `phase20` روی Production نیست |
| کارنامهٔ تحلیل‌ها | ✅ | — |
| فیدِ کدال · بانکِ داده · رصدِ بازار | ✅ | — |
| فرمِ لید | ❌ | `leads` روی Production وجود ندارد |

### Gate 6 — امنیت و پایشِ عملیاتی

| مورد | وضعیت | شاهد یا گلوگاه |
|---|---|---|
| گاردِ زبان | ✅ | `lib/core/vocab.test.ts` در CI |

**Gate 6 = `BLOCKED`.** سه موردِ ❌/❓ (ردیابیِ خطا، Runbookِ حادثه، بکاپ) پیش از
هر رونماییِ عمومی باید بسته شوند.

### Gate 7 — رونمایی

**`NOT_AUTHORIZED`.** Cutover و رونمایی نیازمندِ تأییدِ صریحِ آرش است و در این
مأموریت هیچ بخشی از آن آماده‌سازی نشد، چون پیش‌نیازهایش (Gate 2 عملیاتی،
Gate 3 گذشته، Gate 6 بسته) هیچ‌کدام برقرار نیستند. بستهٔ Launch وقتی معنا دارد
که چیزی برای عرضه آماده باشد؛ ساختنش امروز، سندی می‌شد که هیچ‌چیز را توصیف
نمی‌کند.
