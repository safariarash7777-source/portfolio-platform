# SPEC — پنلِ رصدِ ادمین (اسکرینرِ گلوگاه)

> **نمای سومِ Blueprint** (بخش ۳′: «یک موتور، سه نما»). مخاطب: **فقط آرش** (گیتِ `role=admin`).
> ابزارِ تولیدِ آلفا — یافته‌هایش موتورِ محتوای ناحیهٔ ۳ (صدای مشاور) + کارنامه است.
> منبع: `symbol_history` + `codal_reports` + snapshots (همه append-only، فقط خواندن).
> **این طراحی است؛ اجرا پس از تأیید.** آخرین به‌روزرسانی: ۱۴۰۵/۰۴/۲۷.

## ۰) گلوگاه‌های موردِ رصد (انتخابِ آرش)
۱. جریانِ پولِ حقیقی و قدرتِ خریدار · ۲. تغییرِ عملیاتیِ زودهنگام (ن-۳۰) · ۳. واگراییِ تابلو · ۴. تغییرِ حجم نسبت به میانگینِ **۱۰ روزه**.
*(حباب/NAVِ صندوق‌ها فعلاً خارج از این پنل — بعداً.)*

## ۱) ابعادِ سورت/فیلتر (ستون‌های اسکرینر) — راستی‌آزمایی‌شده روی `symbol_history`

| ستون | منبع (ستون) | محاسبه (در `lib/core`) | واحد/یادداشت |
|---|---|---|---|
| **سرانهٔ خریدِ حقیقی** | `individual_buy_value` / `individual_buy_count` | تقسیم | میلیون تومان (پس از تبدیلِ واحد) |
| **قدرتِ خریدار** | `buyer_power` (موجود) یا سرانه‌خرید/سرانه‌فروشِ حقیقی | نسبت | > ۱ = قدرتِ خریدار بالاتر |
| **ورودِ پولِ حقیقی** | `individual_buy_value − individual_sell_value` | تفاضل | مثبت = ورودِ پول |
| **سهمِ حقوقی از فروش** | `legal_sell_value / value_traded` | نسبت | تشخیصِ عرضهٔ حقوقی |
| **واگراییِ پایانی/آخرین** | `(last_price − close) / close` | نسبت | لختیِ پایانی / تابلوخوانی |
| **نسبتِ حجم (۱۰ روزه)** | `volume / avg(volume, ۱۰ روزِ قبل)` | میانگینِ متحرک | > ۲ ≈ حجمِ مشکوک |
| **YoY نرخ/فروشِ ماهانه** | `codal_reports` ن-۳۰ `period_total_amount` | مقایسهٔ همان ماهِ سالِ قبل | رشدِ واقعی در برابرِ اسمی |
| **شکافِ تولید-فروش** | ن-۳۰ `production_qty − sales_qty` | تفاضل | منفی = تخلیهٔ انبار |
| **سهمِ صادرات** | ن-۳۰ `Σ sales_amount(صادراتی)/Σ` | نسبت | — |

## ۲) رفتارِ پنل
- جدولِ **همهٔ نمادها** پس از **فیلترِ Z** (زیرنمادِ رقم‌دار حذف).
- **سورتِ چندبعدی** (چند ستون هم‌زمان) + **فیلترِ آستانه** (مثلاً قدرت‌خریدار > X و نسبت‌حجم > ۲).
- **پریست‌های گلوگاهِ ترکیبی** (ذخیره‌شده).
- افشا: **عددِ خامِ کاملِ چندبعدی** (نمای ادمین؛ ماسکِ کیفی ندارد).

## ۳) پریست‌های گلوگاهِ ترکیبی (نمونهٔ اولیه)
| پریست | شرط |
|---|---|
| **ورودِ پولِ هوشمند** | قدرت‌خریدار بالا + ورودِ پولِ حقیقی مثبت + نسبتِ حجم > ۲ |
| **بیدارباشِ بنیادی** | جهشِ YoY نرخ/فروشِ ماهانه + شکافِ تولید-فروشِ منفی |
| **واگراییِ تابلو** | فاصلهٔ پایانی/آخرینِ بالا + حجمِ مشکوک (۱۰ روزه) |

## ۴) محاسبات — `lib/core` + تست («یک موتور، سه نما»)
- **`lib/core/marketRadar.ts`** (یا توسعهٔ `screener.ts` موجود) + **`avgVolume10`** (کنارِ `avgVolume30`ِ موجود).
- همه با تستِ `node:test`؛ `null` صادق برای دادهٔ غایب؛ هیچ درون‌یابی.
- **یک سنگ، دو نشان:** همین موتور، نسخهٔ کیفی‌اش نمای عمومی را تغذیه می‌کند.

## ۵) قیدها
- فقط خواندن؛ `symbol_history`/`codal_reports` append-only دست‌نخورده.
- **زیرنمادِ رقم‌دار در مبدأ فیلتر** (قاعدهٔ Z).
- عددِ خامِ کامل فقط اینجا (تحلیلگرِ مجوزدار)؛ **این پنل هرگز به عموم نمی‌رود**.
- گیت: `role=admin` در `middleware.ts` (منبعِ واحدِ حقیقت از `profiles.role`).
- واحدها (میلیون ریال/تومان) در مرزِ محاسبه تثبیت و کامنت (D3)؛ نمایش با `lib/format.ts`.

## ۶) بلاکرها / تصمیم‌های آرش
1. **جای پنل:** مسیرِ جدا `/admin/radar` یا یک تبِ ادمین‌سطح در `/terminal`؟
2. `avgVolume10`: توسعهٔ `lib/core/avgVolume.ts` موجود.
3. راستی‌آزماییِ معنیِ ستونِ `buyer_power` در داده (در برابرِ فرمولِ سرانه).

## ۷) گامِ اجرا (پس از تأیید)
`lib/core/marketRadar.ts` + `avgVolume10` (محاسبات + تست) → کامپوننتِ `AdminMarketRadar` (جدولِ سورت/فیلتر) → مسیرِ ادمین‌گیت‌شده. بدونِ درجِ DB.
