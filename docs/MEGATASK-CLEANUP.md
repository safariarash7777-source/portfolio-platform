**پذیرش:** یک تست خودکار «قرارداد واژگان» به `test:core` اضافه شود که کل `app/` و `components/` را
اسکن کند و کاربرد مثبت واژه‌های ممنوع را fail کند (با allowlist صریح برای جمله‌های نفی‌دار/سلب مسئولیت
و کامنت‌های کد). این تست جلوی برگشت مشکل را برای همیشه می‌گیرد.

### 🔴 C2 — سخت‌سازی امنیتی Supabase (خروجی advisor رسمی، امروز گرفته شد)
- **~۲۲ تابع SECURITY DEFINER که نقش `anon` می‌تواند از REST صدا بزند** — از جمله
  `admin_dashboard_stats`, `admin_risk_distribution`, `add_content_item`. یعنی بازدیدکنندهٔ بی‌لاگین
  می‌تواند آمار داشبورد ادمین را بکشد. → `REVOKE EXECUTE FROM anon, authenticated` برای همهٔ توابع
  ادمین/داخلی؛ فقط توابعی که واقعاً عمومی‌اند بمانند (هرکدام با یک خط دلیل در SQL).
- **۶ تابع بدون `search_path` ثابت** (`deny_mutation`, `payments_guard`, `watchlist_cap`, …) →
  `ALTER FUNCTION … SET search_path = ''` (یا pg_temp الگوی رسمی Supabase).
- افزونهٔ `pg_net` در اسکیمای `public` → انتقال به اسکیمای `extensions`.
- سیاست INSERT همیشه‌درست `waitlist` عمدی است (فرم عمومی) — دست نزن؛ فقط چک کن endpoint
  `/api/waitlist` محدودیت تکرار/طول ورودی دارد.
**تحویل:** فایل `sql/phase15_security.sql` (فقط فایل — اجرا طبق الگوی phase12–14 با کلود انجام می‌شود؛
Manus خودش روی دیتابیس اجرا نکند). **پذیرش:** بعد از اجرا، advisorهای Supabase این چهار دسته هشدار را نشان ندهند و همهٔ صفحات سایت سالم بمانند.
