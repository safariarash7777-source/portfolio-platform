## ۰) محصول در یک پاراگراف

«قطب‌نمای بازار» — پلتفرم فارسی/راست‌به‌چپ تحلیل بازار سرمایهٔ ایران که به سه سؤال
سادهٔ سرمایه‌گذار عادی جواب می‌دهد: **«بازار امروز چه خبر؟»**، **«این نماد خوب است؟»**،
**«با سبدم چه کنم؟»** — با کارنامهٔ عمومیِ غیرقابل‌دستکاری (هش زنجیره‌ای) برای
«تحلیل‌های آرش». مالک محصول مشاور سرمایه‌گذاری دارای مجوز است؛ صداقتِ داده شرط قانونی
است، نه سلیقه.

## ۱) هفت قانون حاکم (نقض هرکدام = رد تحویل)

1. **مدل زبانی هرگز عدد محاسبه نمی‌کند** — همهٔ محاسبات با کد قطعی (SQL/TS/Python).
2. **لاگ تغییرناپذیر از روز اول** — جدول‌های append-only را هرگز UPDATE/DELETE نکن
   (تریگر دیتابیس خودش خطا می‌دهد؛ کد باید طوری نوشته شود که اصلاً تلاش نکند).
3. **از دادهٔ ساختگی سیگنال/تحلیل تولید نشود** — دادهٔ نمونه در UI فقط با برچسب
   صریح «نمونهٔ نمایشی».
4. **آمار رسمی فقط first-print** — تحلیل‌ها فقط از `macro_first_print` می‌خوانند.
5. **دادهٔ بازار append-only** — هر روز ردیف جدید؛ بازنویسی تاریخچه ممنوع.
6. **انسان در حلقه** — هیچ تحلیلی بدون تأیید ادمین منتشر نمی‌شود؛ انتشار خودکار ممنوع.
7. **هیچ سود تضمینی، وعدهٔ بازدهی، یا عدد/آمار/درصد ساختگی** — هرگز، هیچ‌جا.
   دیسکلیمر ثابت پای همهٔ خروجی‌های تحلیلی.

## ۲) آنچه از قبل ساخته شده — دوباره نساز، خراب نکن

- **استک:** Next.js 15 (App Router) · React 18 · TypeScript · Tailwind 3 · Supabase
  (`@supabase/ssr`) · نمودار `lightweight-charts` + `recharts` · آیکون `lucide-react` ·
  فونت Vazirmatn سلف‌هاست با `next/font`. بدون ORM.
- **صفحات موجود:** لندینگ، auth کامل، `/dashboard`، پنل `/admin` (کاربران، وبینار،
  اطلاعیه، محتوا)، `/market` + `/market/stocks` + `/market/funds` (نمای قیمت فعلی)،
  وبینار + پرداخت زرین‌پال، بات تلگرام (`/api/telegram/webhook`) و cron ها.
- **Auth:** در `middleware.ts` مسیرهای `/dashboard` و `/admin` گیت می‌شوند؛ نقش ادمین
  از `profiles.role` خوانده می‌شود (تنها منبع حقیقت نقش).
- **سه‌گانهٔ Supabase:** `lib/supabase/client.ts` (مرورگر) · `server.ts` (RSC/route با
  کوکی) · `admin.ts` (service-role، فقط سمت سرور — **هرگز در کامپوننت کلاینت import
  نشود**).
- **۹ جدول T0 روی Supabase زنده و تست‌شده است** (مهاجرت‌ها اعمال شده؛ متن کامل در
  `sql/terminal_t0.sql`):

| جدول | نقش | نوشتن | خواندن |
|---|---|---|---|
| `symbol_history` | OHLCV روزانه + پول حقیقی/حقوقی + `raw jsonb` | فقط service_role | عمومی |
| `codal_reports` | گزارش‌های کدال، dedup با `source_url` یکتا، `data jsonb` | فقط service_role | عمومی |
| `ime_snapshots` | اسنپ‌شات بورس کالا | فقط service_role | عمومی |
| `macro_first_print` | اولین انتشار آمار رسمی (write-once) | فقط service_role | عمومی |
| `macro_revisions` | اصلاحیه‌های آمار (فقط post-mortem) | فقط service_role | فقط ادمین |
| `signal_drafts` | پیش‌نویس تحلیل — تنها جدول قابل‌ویرایش چرخه | ادمین | ادمین |
| `signals` | تحلیل منتشرشده، هش زنجیره‌ای، تغییرناپذیر | فقط service_role | عمومی |
| `signal_outcomes` | نتیجهٔ بستن هر تحلیل، هش زنجیره‌ای | فقط service_role | عمومی |
| `screener_presets` | فیلترهای ذخیره‌شدهٔ کاربر | مالک | مالک |

- هش زنجیره‌ای `signals`/`signal_outcomes` را **تریگر دیتابیس خودش می‌سازد** —
  کدِ درج فقط ستون‌های عادی را می‌فرستد و به `prev_hash`/`record_hash` دست نمی‌زند.

## ۳) قواعد الزامی کدنویسی

- کل UI فارسی و RTL (`<html lang="fa" dir="rtl">`)؛ چیدمان RTL باید بی‌نقص بماند.
- اعداد/پول/تاریخ **فقط** با هلپرهای `lib/format.ts`: `toPersianDigits` (نمایش)،
  `toLatinDigits` (قبل از اعتبارسنجی ورودی)، `formatToman`، `formatJalali`.
  رقم فارسی یا تاریخ دستی نساز.
- رنگ فقط از توکن‌ها (`tailwind.config.js` + متغیرهای `app/globals.css`:
  `--navy`, `--gold`, `--surface`, `--line`, …). سایه: `shadow-institutional`.
  فونت از CDN لود نشود.
- در محصول به‌جای واژهٔ «سیگنال» بنویس **«تحلیل آرش»** (فقط زبان UI؛ نام جدول‌ها
  تغییر نمی‌کند).
- ذخیره‌سازی append-only/نسخه‌دار؛ upsert مخرب ممنوع.
- منطق endpoint های موجود (مثل `/api/waitlist`) هنگام تغییر ظاهر عیناً حفظ شود.
- پایان هر بسته: `npm run build` سبز + `npm run typecheck` + `npm run lint`.
- هیچ مقدار سکرتی در کد/کامیت/لاگ؛ فقط نام متغیر در `.env.example`.

## ۴) بسته‌های کاری — به همین ترتیب بساز

### WP1 — رلهٔ داده و جمع‌آوری (زیربنای همه‌چیز)

**مسئله:** BrsApi/Tsetmc از خارج ایران در دسترس نیست؛ Vercel خارج است. پس یک
«رلهٔ داخل ایران» لازم است که داده را بکشد و به Supabase بنویسد.

**بساز:**
1. سرویس رلهٔ مستقل (Node یا Python، هرچه ساده‌تر — یک پروسهٔ کوچک با cron داخلی)
   قابل‌استقرار روی هاست ایرانی، با env: `BRSAPI_KEY`, `SUPABASE_URL`,
   `SUPABASE_SERVICE_ROLE_KEY`, `RELAY_TOKEN`.
2. جاب‌های زمان‌بندی‌شده:
   - **روزانه بعد از بستهٔ بازار (۱۳:۳۰ تهران):** برای همهٔ نمادهای بورس/فرابورس یک
     ردیف در `symbol_history` (OHLCV، ارزش/حجم، خرید/فروش حقیقی‌حقوقی، `buyer_power`،
     پاسخ خام در `raw`).
   - **هر ۱۵ دقیقه در ساعت بازار:** اسنپ‌شات سبک برای نمای زنده (می‌تواند در همان
     `symbol_history` با `captured_at` بیاید؛ `trade_date` همان روز).
   - **روزانه:** فهرست اطلاعیه‌های جدید کدال → درج در `codal_reports` (dedup با
     `source_url`؛ `report_kind` از کد نامهٔ کدال: `ن-۱۰`، `ن-۳۰`، `ن-۵۰`…).
   - **روزانه:** اسنپ‌شات بورس کالا → `ime_snapshots`.
3. درج‌ها **فقط insert**؛ در خطای duplicate (کدال) رد شو، update نکن.
4. لاگ سلامت: جدول جدید `ingest_runs` (id, job, started_at, finished_at, rows, ok,
   error) — این جدول append-only لازم نیست ولی نوشتنش فقط service_role.
5. در Next.js یک endpoint ادمین `/api/admin/ingest-status` که آخرین اجرای هر جاب را
   نشان بدهد + کارت وضعیت در `/admin`.

**پذیرش:** بعد از ۳ روز اجرا، برای ≥۹۰٪ نمادها هر روز دقیقاً یک ردیفِ پایانی در
`symbol_history` هست؛ هیچ UPDATE ای در لاگ Supabase دیده نمی‌شود؛ کلیدها فقط در env.

### WP2 — صفحهٔ عمومی «امروزِ بازار» (بدون لاگین)

مسیر: `/market` را ارتقا بده (منطق فعلی را نگه دار، نما را کامل کن).

**بساز:**
- بالای صفحه: شاخص کل و هم‌وزن + درصد تغییر، ارزش معاملات، **ورود/خروج پول حقیقی کل
  بازار** (جمع از `symbol_history` روز جاری).
- «۵ روایت امروز»: بیشترین ورود پول حقیقی، بیشترین حجم مشکوک (حجم ≥ ۳× میانگین
  ۳۰ روزه)، بیشترین رشد/افت گروه‌های صنعت، تازه‌ترین گزارش‌های مهم کدال (از
  `codal_reports`).
- هر کارت یک جملهٔ فارسی سادهٔ **template-ای** (نه تولید LLM) با عدد واقعی؛ اگر داده
  نیست، کارت مخفی — عدد جایگزین ممنوع.
- تاریخ جلالی با `formatJalali`؛ همهٔ اعداد با `toPersianDigits`.

**پذیرش:** صفحه بدون لاگین باز می‌شود؛ با دادهٔ خالی هم نمی‌شکند (کارت‌ها مخفی)؛
build سبز؛ RTL بی‌نقص در موبایل.

### WP3 — دیده‌بان (screener) — `/dashboard/watch`

**بساز:**
1. **جدول زندهٔ نمادها گروه‌بندی‌شده با صنعت** (آکاردئون در موبایل): آخرین/پایانی +٪،
   حجم، ارزش، قدرت خریدار حقیقی. مرتب‌سازی روی هر ستون.
2. **فیلترسازِ شرطی ترکیبی** (AND بین شرط‌ها): فیلدها = تغییر قیمت، حجم نسبت به میانگین
   ۳۰ روزه، ورود پول حقیقی، قدرت خریدار، صنعت. UI چیپ/فرم ساده، خروجی JSON در
   `screener_presets.config`.
3. ذخیره/بازخوانی پریست‌ها برای کاربر لاگین‌شده (RLS مالک از قبل هست).
4. **واچ‌لیست شخصی**: ستارهٔ نماد → جدول جدید `watchlist_items`
   (id, user_id, symbol, created_at؛ RLS مالک مثل `screener_presets`).
5. دادهٔ جدول از `symbol_history` (آخرین `captured_at` هر نماد) از طریق یک route
   handler با کش کوتاه (revalidate ۶۰ ثانیه)؛ اتصال مستقیم کلاینت به جدول بزرگ ممنوع.

**پذیرش:** کاربر می‌تواند فیلتر «حجم ≥ ۲× میانگین + ورود پول حقیقی مثبت» را بسازد،
ذخیره کند، و بعد از رفرش دوباره اجرا کند؛ نتیجه با SQL دستی یکسان است.

### WP4 — موتور بنیادی کدال (I1) — مهم‌ترین تمایز ما

**ورودی:** فایل‌های اکسل رسمی کدال (ن-۱۰ صورت مالی، ن-۳۰ فعالیت ماهانه) — آپلود دستی
ادمین در فاز اول؛ بعداً از رله.

**بساز:**
1. صفحهٔ ادمین `/admin/codal` با آپلود اکسل → پارسر سمت سرور → درج در
   `codal_reports` با `data jsonb` نرمال‌شده. اسکیمای `data` برای ن-۱۰:
   دورهٔ منتهی، ۱۲ماهه/میان‌دوره، حسابرسی‌شده/نشده، تلفیقی/اصلی، تجدید ارائه،
   واحد (میلیون ریال)، اقلام صورت سود و زیان (فروش، بهای تمام‌شده، سود ناخالص/
   عملیاتی/خالص، EPS). برای ن-۳۰: **به تفکیک هر محصول**: نام، مقدار تولید، مقدار
   فروش، نرخ فروش، مبلغ، داخلی/صادراتی + جمع دوره و تجمیعی سال مالی.
2. **ماژول محاسبات** (TS خالص، تست‌دار): P/E TTM فصلی، حاشیه‌های سود سه‌گانه،
   رشد فصل نسبت به **فصلِ مشابه سال قبل** (الگوی استاندارد ما)، میانگین ۴ فصل،
   سود خالص فصلی و تجمیعی.
3. **۵ خروجی نموداری** (قرارداد قطعی — recharts، توکن‌های برند، بدون واترمارک شلوغ):
   1) روند P/E فصلی TTM + خط‌چین میانگین ۴ فصل + باکس خلاصه (قیمت/EPS/P/E فعلی)
   2) حاشیهٔ سود عملیاتی هر فصل در برابر فصل مشابه سال قبل
   3) سود خالص فصلی (۳ سال) + تجمیعی از ابتدای سال مالی
   4) پای‌چارت فروش داخلی/صادراتی + سهم محصولات (از ن-۳۰)
   5) سری زمانی نرخ و مقدار فروش **هر محصول** (ماهانه، از ن-۳۰)
4. **۴ فیلتر «گزارش خوب»** برای دیده‌بان (خروجی boolean/امتیاز از همین داده‌ها):
   رشد نرخ فروش محصول اصلی ۳ ماه پیاپی · رشد هم‌زمان نرخ و مقدار · فروش ماهانه
   بالاتر از میانگین ۱۲ ماه · جهش حاشیهٔ سود نسبت به فصل مشابه. (هیچ‌کدام «توصیهٔ
   خرید» نیست — فقط فیلتر داده؛ برچسب UI: «گزارش قوی».)

**پذیرش:** اکسل واقعی فملی (آرش می‌دهد) آپلود شود و هر ۵ نمودار با اعداد قابل‌راستی‌آزمایی
با خودِ کدال رندر شود؛ محاسبات تست واحد داشته باشند؛ هیچ عددی گرد/جعل نشود.

### WP5 — صفحهٔ نماد — `/symbol/[symbol]`

**بساز:**
- سربرگ: نام/نماد/صنعت، قیمت و تغییر، تاریخ جلالی آخرین به‌روزرسانی.
- **کارت امتیاز سه‌محوره**: بنیاد (از WP4) · روند و تابلو (از `symbol_history`:
  روند قیمت، پول حقیقی، قدرت خریدار) · ریسک (نوسان ۹۰ روزه، عمق معاملات). هر محور
  ۰–۱۰۰ با **فهرست «چرا»** (هر امتیاز = قواعد شفاف کدشده، نه LLM). محوری که داده
  ندارد: خاکستری با برچسب «به‌زودی» — عدد ساختگی ممنوع.
- یک **جملهٔ خلاصهٔ فارسی template-ای** از روی امتیازها (قالب ثابت، جای‌گذاری عدد واقعی).
- تب‌ها: نمودار قیمت (`lightweight-charts`) · بنیادی (۵ چارت WP4) · تابلو (پول
  حقیقی/حقوقی روزانه).
- دیسکلیمر ثابت پایین صفحه (متن از آرش گرفته شود؛ placeholder تا آن موقع:
  «این تحلیل توصیهٔ خرید یا فروش نیست»).

**پذیرش:** `/symbol/فملی` با دادهٔ واقعی کار کند؛ لینک از دیده‌بان و «امروزِ بازار»
به این صفحه؛ share-friendly (og-image مرحلهٔ بعد، الان فقط متادیتا).

### WP6 — «تحلیل‌های آرش» + کارنامهٔ عمومی

**بساز:**
1. صفحهٔ ادمین `/admin/analyses`: فهرست `signal_drafts` (pending) → دکمهٔ تأیید/رد.
   تأیید = درج ردیف در `signals` با service_role در route handler (هش را تریگر
   می‌سازد) + به‌روزکردن status پیش‌نویس. رد = status=rejected + یادداشت.
2. فرم «تحلیل دستی» ادمین → درج مستقیم در `signal_drafts` (source='manual').
3. بستن تحلیل: فرم ادمین → درج در `signal_outcomes` (target/stop/manual_close/expired).
4. صفحهٔ عمومی `/analyses`: کارت هر تحلیل منتشرشده (نماد، جهت، تاریخ جلالی، دلایل)
   + وضعیت (باز/بسته و نتیجه) + **نشان «ثبت‌شده با هش زنجیره‌ای»** با توضیح ساده
   + صفحهٔ کارنامه: جدول همهٔ تحلیل‌های بسته‌شده با نتیجهٔ واقعی (برد و باخت،
   هر دو — فیلترکردن باخت‌ها ممنوع).
5. **هیچ محاسبهٔ «درصد موفقیت» تا وقتی ≥۱۰ تحلیل بسته نشده** — قبل از آن فقط فهرست خام.

**پذیرش:** چرخهٔ کامل پیش‌نویس→تأیید→انتشار→بستن روی دیتابیس واقعی کار کند؛ تلاش برای
ویرایش تحلیل منتشرشده با خطای دیتابیس رد شود (این رفتار درست است، هندل و پیام مناسب)؛
صفحهٔ عمومی بدون لاگین باز شود.

### WP7 — بات تلگرام per-symbol (بک‌لاگ — فقط بعد از WP4 و WP5)

روی بات موجود (`/api/telegram/webhook`): کاربر «فملی» می‌فرستد → دکمه‌های موضوعی
(قیمت و تابلو / سود و حاشیه / گزارش ماهانه / کارت امتیاز) → جواب = همان خروجی‌های
WP4/WP5 در قالب متن/عکس + لینک صفحهٔ نماد. هیچ محاسبهٔ جدیدی ندارد؛ فقط قالب تلگرامی
همان داده‌هاست.

## ۶) چیزهایی که عمداً الان نمی‌سازیم (نساز)

Kafka/Redis/Qdrant/FastAPI/PyTorch و هر زیرساخت سنگین · بک‌تست و walk-forward و
DSR (فاز I3/I4) · انتشار خودکار تحلیل بدون تأیید انسانی · اپ موبایل · پرداخت/اشتراک
جدید (فعلاً همه‌چیز رایگان) · چت‌بات LLM ای که عدد تولید کند.

## ۷) کارهایی که فقط آرش انجام می‌دهد (بلاکرهای بیرونی)

- خرید پلن کامل BrsApi و گذاشتن `BRSAPI_KEY` در env رله.
- تهیهٔ هاست داخل ایران برای رله (WP1).
- ارسال اکسل کدال فملی (۱۲ماههٔ حسابرسی‌شده + چند ن-۳۰) برای WP4.
- چرخش ۳ سکرت لورفتهٔ قبلی (BRSAPI_KEY، RELAY_TOKEN، کلید 21st.dev) و ست‌کردن
  GitHub Secrets مربوط به `SITE_URL`/`CRON_SECRET`.
- جلسهٔ «استخراج سبک»: ۵–۱۰ قاعدهٔ صریح سبک شخصی برای موتور پیش‌نویس تحلیل.
- متن نهایی دیسکلیمر حقوقی.

## ۸) تعریف «تمام» برای هر بسته

کد روی برنچ فیچر جدا + شرح تغییرات · `npm run build` و `typecheck` و `lint` سبز ·
هیچ UPDATE/DELETE روی جدول‌های append-only · هیچ عدد ساختگی/وعدهٔ بازدهی در UI ·
RTL و فارسی با هلپرهای `lib/format.ts` · اسکرین‌شات موبایل + دسکتاپ · فهرست
فایل‌های تغییرکرده + چک‌لیست تستی که آرش خودش باید انجام دهد.
