## ۰) معماریِ ورودِ داده — آن‌طور که واقعاً هست

منابعِ ایرانی به IPِ خارج از ایران ۴۰۳ می‌دهند و سایت روی Vercel است. پس
یک سرویسِ واسط **داخلِ ایران** لازم است. آن سرویس در همین مخزن است:

```
tgju · fipiran · brsapi
        │
        ▼
   relay/  (Node، روی لیارا، داخل ایران)
        │  push با service_role
        ▼
   Supabase  (جهانی)
        │  read با anon
        ▼
   سایت (Vercel)
```

شاهد: [`relay/README.md`](../relay/README.md) · [`relay/liara.json`](../relay/liara.json)

> **تصحیحِ یک باورِ رایج در اسنادِ قبلی.** جاهایی نوشته شده «رله بیرون از این
> مخزن است و دوره‌اش تضمین‌شده نیست». نادرست است: کدِ رله اینجاست و
> تناوب‌هایش در کد عددِ صریح دارند (بخشِ ۲). هر آستانهٔ تازگی باید از این

## ۵) نشانه‌های خرابی — چه چیزی «خراب» را از «خالی» جدا می‌کند

| نشانه | معنا | ابزارِ موجود |
|---|---|---|
| `sources.<x>.error = "HTTP 403"` | رله بیرونِ ایران اجرا می‌شود یا IP بلاک است | `<relay>/debug` |
| `supabase.enabled = false` | env روی لیارا ست نشده؛ سایت هیچ داده‌ای نمی‌گیرد | `<relay>/debug` |
| `supabase.ok = false` | انتشار به Supabase شکست خورد؛ سایت آخرین اسنپ‌شاتِ موفق را نشان می‌دهد | `<relay>/debug` |
| `irDiag.counts = 0` با `status 200` | جدول خالی است؛ رله چیزی push نکرده | `/api/market?diag=1` |
| `irDiag.source = "relay"` | Supabase خالی بود و از مسیرِ دوم خوانده شد | `/api/market?diag=1` |

هر دو ابزار **از قبل وجود دارند** و سکرت نشان نمی‌دهند (`relay/README.md`).
میزِ هوشمندی باید همین‌ها را بخوانَد، نه اینکه شاخصِ تازه بسازد.
