# مالکیت سرویس‌ها و مسئولیت اجرا

بازبینی: 2026-11-14. مالک محصول و حساب‌ها: **آرش صفری**.
این سند مسئولیت را مشخص می‌کند؛ وضعیت انتشار و مانع در [COMMAND-CENTER](./COMMAND-CENTER.md) و نقشهٔ اتصال در [PRODUCTION-ARCHITECTURE](./PRODUCTION-ARCHITECTURE.md) است.

| حوزه | مسئول مأموریت جاری | خروجی مسئولیت |
|---|---|---|
| هماهنگی | هماهنگ‌کنندهٔ موجود Codex در همین مأموریت | یک دفتر وضعیت، کنترل تغییر مشترک و تفکیک کد/تست/انتشار/پذیرش |
| سایت/Vercel | همان هماهنگ‌کننده | نسخهٔ frontend، اتصال واقعی، دسترسی و تجربهٔ کاربر |
| Relay/Liara PaaS | همان هماهنگ‌کننده | دریافت، کنترل درخواست، scheduler، cursor و دو چرخهٔ طبیعی |
| DB/Auth/Liara VPS | همان هماهنگ‌کننده در اختیار معتبر | مقصد صحیح، RLS، migration و حفظ داده؛ نه نصب موازی |
| کدال و صحت مالی | همان هماهنگ‌کننده | هویت/دوره/واحد، پوشش قالب و علت رد، نه صرف دریافت فایل |
| مالی عضو/مشاوره | همان هماهنگ‌کننده | مسیر عضو عادی، مالکیت داده، حفظ نسخه و پذیرش انتهابه‌انتها |
| پژوهش/ایجنت‌ها | همان هماهنگ‌کننده؛ بررسی محتوایی آرش | ابزار و بودجه مشخص، خروجی قابل بررسی و شواهد اجرای واقعی |
| رسانه/آموزش/طراحی | همان هماهنگ‌کننده؛ جهت محتوایی و بصری آرش | هویت آرش، محتوای واقعی و دسترسی متناسب با عضو |
| حساب و هزینهٔ جدید | آرش | تصمیم مالی؛ تعمیر مجوز خرید تازه نیست |
| DNS و سرویس‌های تاریخی | مالک حساب آرش؛ نگهدارندهٔ دائمی تأییدنشده | موجودی و دسترسی تازه؛ بدون خاموشی بر اساس سند قدیمی |

هماهنگ‌کننده مسئول این مأموریت است؛ این عنوان تضمین اپراتور AI همیشه‌فعال نیست. پس از پایان نوبت، فقط سرویس‌ها و زمان‌بندی‌های مستقر ادامه دارند. نگهدارندهٔ دائمی پاسخ‌گو به هشدار و جانشین او هنوز باید به‌صورت عملیاتی تعیین و آزموده شود.

## اختیار و هماهنگی

- آرش اصلاح، آزمون و انتشار بسته‌های آمادهٔ این مأموریت را صریحاً مجاز کرده؛ برای همان کار تأیید تکراری لازم نیست.
- تغییر مشترک و انتشار زیر نظر هماهنگ‌کننده است؛ هر منبع در لحظه یک نویسندهٔ فعال دارد.
- واگذاری نیازمند محدوده، مالک، شاخه، ورودی، خروجی و معیار پذیرش است؛ ارسال وظیفه تحویل نیست.
- migration، حذف داده، خرید و تغییر حساس خارج از اختیار موجود با مجوز کلی تعمیر توجیه نمی‌شود.
- مانع باید علت، شاهد، مسئول رفع و اقدام بعدی داشته باشد؛ «لیارا خراب است» علت دقیق نیست.
- کلید، رمز و دادهٔ عضو در سند عمومی قرار نمی‌گیرد. سابقهٔ مالکیت قبلی در Git محفوظ است.
