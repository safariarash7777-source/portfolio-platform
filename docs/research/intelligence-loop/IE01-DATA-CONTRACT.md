# IE01 — قرارداد اجرا و شواهد چهار حالت آفلاین

۲ اکتبر ۲۰۲۶، تهران. دامنهٔ مجاز: harness، fixture و اسناد مستقل؛ کد محصول، سرویس و دادهٔ زنده تغییر نمی‌کنند. این مرحله جایگزین وضعیت «اجرا نشده» در آماده‌سازی اولیه است؛ [پروندهٔ اولیه](history/IE01-EVIDENCE-20261001.json) بدون تغییر حفظ شده است.

**نتیجه: چهار حالت اجرا شدند؛ دو PASS و دو FAIL. صحت مالی گزارش واقعی و پذیرش Production همچنان اثبات نشده‌اند.** مرجع جزئیات: [شواهد اجرا](IE01-EVIDENCE.json)، [اجرای تکراری](IE01-REPLAY.json) و [گزارش تحویل](IE01-RESULT.md).

در [manifest نسخه](../../../scripts/research/ie01/baseline.json)، blobهای شش فایل منتخب میان این چهار SHA تطبیق دارند: پارسر، transport واردشده، engine، انتخاب اصلاحیه، بایگانی ونوین و آزمون تاریخی. hash فایل‌ها پیش و پس از اجرا کنترل می‌شود. `codeSHA` شاهد، SHA پایهٔ ثابت است؛ commit بعدی harness، SHA جدید کد محصول نیست. FOLLOWUP03 از نظر هویت نسخه تعیین شده است؛ پوشش زنده و محدودیت‌های مالی باز می‌مانند.

## منشأ و مجهول‌ها

ورودی C1 همان byteهای `relay/fixtures/vanovin-n10-fy1404.html` است. توضیح آزمون تاریخی آن را گزارش عمومی کدال ونوین معرفی می‌کند. جست‌وجوی فایل‌های checkout ثابت، تاریخچهٔ Git بایگانی، اسناد جهت محصول و DEV07، گزارش‌های ذخیره‌شدهٔ ممیزی بازار و خروجی‌های FX، URL واقعی اطلاعیه یا زمان دریافت را پیدا نکرد. تنها host در URLهای داخل HTML، `www.w3.org` است و منشأ ناشر نیست.

`sourceUrl`، `announcementId`، `sourceAt` و `capturedAt` **null** هستند. commit ایجاد بایگانی `5fd94b3ccdd4f682898edec7a6f33451f2918936` با زمان `2026-07-17T06:52:16Z`، زمان Git است و زمان انتشار یا دریافت نیست. اصل گزارش دومِ اصلاحیه موجود نیست. واحد مرجع «میلیون ریال» از قرارداد آزمون تاریخی/کد است؛ تطبیق مستقل سربرگ همان صورت بانک انجام نشده است. حقوق انتشار نیز تأیید نشده‌اند.

## قرارداد خروجی

| فیلد | قاعدهٔ ثبت |
|---|---|
| `dataClass` | بایگانی با ادعای منشأ عمومی، یا fixture مصنوعی صریح؛ با هم مخلوط نشوند |
| `sourceAt` / `capturedAt` | فقط زمان واقعیِ قابل استناد؛ در این پرونده null |
| `startedAt` / `calculatedAt` | زمان واقعی شروع/پایان اجرای parser و تابع قطعی، UTC با Z؛ زمان ساخت fixture نیست |
| `codeSHA` / `parserVersion` | SHA پایهٔ ثابت و نسخهٔ پارسر موجود؛ digest فایل‌ها در manifest |
| `inputDigest` | SHA256 سریال‌سازی دقیق UTF-8 JSON ورودی case؛ hash byteهای بایگانی و فایل fixture جدا ثبت شده‌اند |
| `outputDigest` | SHA256 JSON خروجی واقعی؛ شامل نتیجهٔ parser و engine، بدون timestamp اجرایی |
| `unit` | واحد خروجی مشاهده‌شده، حتی اگر قرارداد را نقض کند؛ unit مورد انتظار در case مشخص است |
| `coverage` | شمار fields مرجع و cases؛ پوشش کل بازار، اصالت ناشر و تاریخ‌های نامعلوم null/false |
| `status` | نتیجهٔ همین آزمون محدود؛ PASS به معنی تأیید مالی/محیط هدف نیست |

عددهای مالی خروجی فقط از `normalizeN10` و `lib/core/engine.ts:computeRatios` موجود تولید می‌شوند. harness هیچ guard محصولی را برای PASS اضافه نمی‌کند. oracleهای نسبت صرفاً برابری حاصل‌ضرب برای آزمون فرمول‌اند، نه engine دوم. قیمت، ارزش‌گذاری و نمرهٔ سرمایه‌گذاری ساخته نمی‌شود؛ P/E بدون قیمت null است.

## بازتولید، امنیت اجرا و توقف

از ریشهٔ شاخه، با Node `24.19.0` (یا Node24 سازگار با type stripping):

```powershell
node scripts/research/ie01/run.mjs
node scripts/research/ie01/run.mjs IE01-REPLAY.json
node --test scripts/research/ie01/run.test.mjs
```

دو فرمان اول **exit=1** می‌دهند، چون دو شکست قرارداد حفظ می‌شوند؛ خروجی قبل از خروج نوشته می‌شود. آزمون سلامت harness باید PASS شود و شکست محصول را به موفقیت تبدیل نمی‌کند. digest payload دو اجرا بدون timestamp یکسان است. dependency، lockfile، package.json و فایل محصول تغییر نکرده‌اند؛ نصب dependency لازم نیست. Node24 مستقیم TypeScript توابع موجود را می‌خواند؛ هشدار module type سبب تغییر تنظیمات محصول نمی‌شود.

manifest بر byteهای checkout ویندوز همین شاهد بسته شده است. اگر checkout دیگری حتی با تبدیل LF/CRLF byteهای منابع را تغییر دهد، harness عمداً متوقف می‌شود؛ شاهد جدید باید digest واقعی خودش را با blob پایه تطبیق دهد و manifest مستقل بسازد. موفقیت بدون تطبیق byteها ادعا نمی‌شود. `.gitattributes` فقط در دو پوشهٔ IE01، تبدیل byteهای fixture/evidence را متوقف می‌کند؛ فایل محصول یا قواعد سراسری Git تغییر نکرده‌اند.

پیش از import محصول، fetch، HTTP/HTTPS، socket، DNSهای منتخب و child-process با guard بسته و envهای مرتبط از همان پردازش حذف می‌شوند. کد اجرا فقط خواندن فایل و توابع pure نام‌برده است؛ هیچ DB، سرویس، upstream، مدل یا runner عام فراخوانی نمی‌شود. این guard کنترل harness است، گارد عملیاتی محصول نیست.

مالک دادهٔ موجود/FOLLOWUP04 باید دو شکست را بررسی و نگاشت/رفع مستقل پیشنهاد کند. اصلاح parser/relay/engine، تغییر schema، ترمیم تاریخچه و مصرف اختیاری در این PR نیست. IE02/IE03، انتشار و ده روز تمرین انسانی آغاز نشده‌اند. ادامه تا واگذاری بعدی متوقف است.
