# START-A — طرح اجرای محدود

## قرارداد خواندن/نوشتن موجود

قرارداد و درخواست `lib/consultation/{contracts,request,server}.ts`؛ گردش نسخه/تأیید در `sql/consultation_workflow.sql`؛ رابط `ConsultationWorkspace`, `RecommendationEditor`, `SessionCard` و readback مشترک موجود. ثبت مالی از قراردادهای موجود cashFlow/goals و دفتر holdings می‌آید؛ دفتر موازی ساخته نمی‌شود.

## ترتیب

1. خواندن تطبیقی مسیرهای فعلی و آزمون‌های موجود، به‌ویژه کنترل basis/research و حقوق خدمت؛ بدون بازسازی roster/replies.
2. اجرای آزمون رفتاری پایه و شناسایی مقصد آزمون ایزوله قابل‌استفاده. عدم دسترسی مقصد، فقط شاهد native را محدود می‌کند و مانع آزمون محلی مستقل نیست.
3. اگر نقص بازتولید شد، نخست آزمون شکست‌خورنده، سپس کوچک‌ترین اصلاح در محدوده و آزمون هدفمند. اگر رفتار درست بود، رسید پذیرش با حدود دقیق کافی است.
4. نتیجه قابل بازکردن با SHA، محیط، فرمان، محدودیت، diff و روش برگشت؛ سپس ادامه مستقل روی شکاف بعدی همین مسیر.

## پذیرش و برگشت

اجرای داده ساختگی دو عضو، نسخه مالی، رضایت/لغو، مبنای جدید، سؤال/پاسخ، read/save شکست‌خورده و عدم تغییر موجودی. build/typecheck/lint متناسب با اصلاح؛ آزمون گران فقط پس از تغییر/شکست لازم تکرار می‌شود. برگشت کد با revert برش محدود؛ migration و تغییر داده تولید در این مرحله وجود ندارد. هیچ ظاهر تازه بدون preview، پذیرفته‌شده یا منتشر معرفی نمی‌شود.

## ادامهٔ مجاز پس از پذیرش پایه

دو وضعیت `partial`/`not_done`: ابتدا آزمون قرارداد شکست‌خورنده، سپس افزودن enum/اعتبارسنجی و کنترل مسئولیت به read/write، فرم جزئیات در SessionCard و نمایش تاریخچه. SQL افزایشی با CLI موجود به‌عنوان candidate تولید و در همان harness ایزوله بررسی می‌شود؛ فایل پایه نصب‌شده بازنویسی نمی‌شود. همه تاریخچه و توابع خارج دامنه با fingerprint/ACL بررسی شوند. rollout: schema سازگار و آزمون مقصد پیش از فعال‌سازی writer جدید؛ پس از وجود رویداد جدید، برگشت reader قدیمی مجاز نیست. rollback SQL فقط با guard عدم وجود دو وضعیت تازه اجراپذیر است.

PR بر پایه شاخه باز PR314، بدون تکثیر آن در PR مستقل روی main؛ CI و Preview پروژه موجود. صفحه preview مصنوعی به production راه داده نمی‌شود. هیچ ابزار نیازمند پاسخ کاربر استفاده نمی‌شود.
