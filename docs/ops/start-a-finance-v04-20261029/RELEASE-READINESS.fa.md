# بسته انتقال START-A و حدود نصب — ۲۹ اکتبر ۲۰۲۶

این سند مکمل تحویل PR334 است؛ مرجع مشترک وضعیت را هماهنگ‌کننده به‌روز می‌کند. بسته انتقال، مجوز نصب نیست. مقصد اصلی sandbox نیست و حساب‌های بازنشسته برای آزمون دوباره فعال نمی‌شوند.

## نسخه و بایت‌های قابل انتقال

کد محصول `b08687b233d5fe1317748b6adff61653d58dadd8` بر PR314 با مبنای `2a8b50b0ce41f5fe15ba629cac4838314d8ce39c` است. PR335 فقط نمونه رابط است و وارد محصول نمی‌شود. هر تغییر بعدی در کد باید دوباره با این بسته تطبیق داده شود.

فرمان زیر فقط شش فایل بازبینی‌شده را از Git محلی به پوشه **جدید** منتقل و MANIFEST تولید می‌کند؛ مقصد نصب، رمز، شبکه و اجرای SQL ندارد. والد مقصد باید از قبل وجود داشته باشد:

```text
node scripts/testing/consultation-feedback/export-release.mjs <new-artifact-directory>
node --test scripts/testing/consultation-feedback/export-release.test.mjs
```

ناسازگاری قالب خط وجود دارد: installer موجود PR314 هش CRLF فایل پایه (`4b2ca…`) و هش LF دو افزونه را انتظار دارد. blob فایل پایه در Git با LF، هش `4e389…` دارد. انتقال عادی checkout ویندوز یا لینوکس هر دو می‌تواند پیش از DDL متوقف شود. exporter ابتدا هش دقیق blobهای Git را کنترل می‌کند، فقط فایل پایه را به بایت‌های CRLF مورد انتظار guard تبدیل می‌کند و **همه** هش‌های خروجی را دوباره تطبیق می‌دهد. installer و guard تغییر نکرده‌اند. فایل پایه صرفاً ورودی کنترل هش است و دوباره اجرا نمی‌شود. تبدیل یا نرمال‌سازی خودسرانه روی سرور مجاز نیست.

داخل آرشیو، `verify-transfer.py` با Python استاندارد روی Linux/Windows اجرا می‌شود: `python3 verify-transfer.py .`. هش‌های مستقلِ pinشده را با همه فایل‌ها و manifest تطبیق می‌دهد؛ سپس فقط تابع خالص ساخت payload در installer دقیق و هش‌شده را فراخوانی می‌کند. به‌صورت ماشینی ثابت می‌کند ورودی اجرایی PR314 فقط roster/replies است و baseline حتی با جایگزینی sentinel وارد payload نمی‌شود. مسیر اجرای command در این بررسی ممنوع شده؛ نه installer.run و نه SQL اجرا می‌شوند. هش خود آرشیو و MANIFEST باید از رسید مستقل فرستنده تطبیق داده شوند؛ manifest داخل آرشیو به‌تنهایی اثبات اصالت نیست.

## ترتیب تحویل و توقف‌ها

1. هماهنگ‌کننده هویت مقصد، مالک نویسنده، image/container کامل، کد واقعاً مستقر و وضعیت اشیای نصب‌شده را با شاهد تازه ثبت کند. `preflight-readonly.sql` فقط catalog/هش بدنه توابع را می‌خواند؛ نه ردیف عضو یا متن بدنه تابع. شناسه DB به‌تنهایی هویت محیط را ثابت نمی‌کند.
2. حداقل **۱۰GiB** فضای آزاد، helper دقیق پشتیبان، checkpoint حداکثر ۲۴ساعته، پشتیبان رمزگذاری‌شده مستقل و بازیابی برابر روی کپی جدا اثبات شوند. شواهد تاریخی و CI جای آن‌ها نیست. پاک‌سازی، ارتقا و کاهش guard در این بسته وجود ندارد.
3. اگر PR314 نصب نشده، همان installer موجود با attestation واقعی و rehearsal روی کپی اجرا شود؛ اجرای source تنها در اختیار هماهنگ‌کننده و مجوز جاری اوست. این helper فقط roster/replies را نصب می‌کند؛ migration دو وضعیت START-A را **اجرا نمی‌کند**. شکست/ابهام با readback بررسی شود و intent قبلی پاک نشود.
4. migration START-A و rollback دقیق در MANIFEST هستند، اما هنوز adapter عملیاتیِ مجاز و متصل به lock/intent/backup/readback برای اجرای آن‌ها تأیید نشده است. اجرای دستی مستقیم روی primary، جای آن را نمی‌گیرد. نسخه نهایی adapter باید ابتدا روی مقصد مجاز آزموده شود. بنابراین «بسته انتقال آماده» با «نصب کامل آماده اجرا» یکی نیست.
5. reader جدید و SQL توسعه‌یافته باید با ترتیب rollout سازگار منتشر شوند؛ writer تازه پیش از reader سازگار و SQL تأییدشده در دسترس عضو قرار نگیرد. reader قدیمی enum تازه را نمی‌خواند. rollback قبل از تاریخچه جدید تعریف/ACL قبلی را برمی‌گرداند؛ پس از `partial/not_done`، rollback قدیمی عمداً PT409 می‌دهد. در آن حالت تاریخچه حفظ و reader سازگار نگه داشته شود؛ برگشت خودکار برنامه به reader قدیمی ممنوع است.
6. پذیرش native روی مقصد **مجازِ شناسایی‌شده** با حساب ساختگی تازه، ورود واقعی Auth، API و بازخوانی مستقل انجام شود: عضو A/B، مشاور/مدیر نامرتبط، رضایت/لغو، مبنای مالی تغییرکرده، تأیید/انتشار جدا، دو وضعیت تازه و تاریخچه. عدم تغییر دارایی پس از feedback نیز مستقل اثبات شود. پذیرش انسانی آرش جداست.

## مشاهده تازه و مالک ادامه

- SSH مستقیم به مقصد موجود با timeout هشت‌ثانیه‌ای پاسخ نداد؛ این شاهد رد کلید یا خرابی sshd نیست. هویت جاری، نسخه اشیای اصلی، ظرفیت و پشتیبان تازه **تأیید نشده‌اند**. عدد ۶٫۵GiB مربوط به مشاهده پیشین است و اندازه‌گیری امروز نیست.
- دریافت وضعیت PR314/334/335 از connector گیت‌هاب با خطای transport شکست خورد. آخرین CI سبزِ ثبت‌شده محفوظ است؛ وضعیت remote تازه از این تلاش نتیجه نمی‌شود.
- اسناد پذیرش advisor-next URL محلی `127.0.0.1:4318` دارند؛ lab native قبلی `localhost:32189` محلی و بازنشسته است. هیچ‌کدام sandbox آنلاین جاری نیستند. URL پیش‌نمایش PR335 با داده حافظه‌ای نیز native نیست. از اسناد این برش مقصد آنلاینِ جدا و دارای مجوز شناسایی نشد.
- هماهنگ‌کننده `01a187f6-30e9-7fb1-8cde-d60fd036f76b/local` مالک بررسی ظرفیت، مقصد آنلاین و اختیار نصب است. مجری START-A مالک بسته انتقال/محدودیت entitlement و ادامه adapter پس از تعیین مقصد و حدود اجراست. هیچ DDL، حساب، پیام، تأیید واقعی، نصب یا انتشار عملیاتی در این برش انجام نشده است.
