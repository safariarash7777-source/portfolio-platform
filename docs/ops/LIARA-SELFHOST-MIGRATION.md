|---|---|---|

| **خودِ دیتابیس** | ✅ سالم | `ACTIVE_HEALTHY`، `default_transaction_read_only=off`، پرس‌وجوی مدیریتی کار می‌کند — **ولی این سلامتِ سرویس نیست** |

## ۳. مقایسهٔ دو گزینه

| معیار | **الف) Supabaseِ خودمیزبان روی سرورِ مجازیِ لیارا** | **ب) PostgreSQLِ مدیریت‌شدهٔ لیارا + جایگزین‌ها** |
|---|---|---|
| تغییرِ کد | **یک خط** (CSP، در همین PR) + متغیرهای محیطی | Auth جدید (۳۱ فراخوانی + جریان‌های ایمیل)، جایگزینِ PostgREST یا بازنویسیِ ۴۳+۲۶ فایل، `auth.uid()` و نقش‌های `anon/authenticated`، cron |
| سازگاریِ داده و نقش‌ها | همان تصویرِ `supabase/postgres:17.6.1.x` که Production روی آن است (`17.6.1.104`): همان نقش‌ها، همان افزونه‌ها | افزونه‌های رسمی فقط PostGIS و pgvector (`docs.liara.ir/dbaas/postgresql/extensions`)؛ `pg_cron`، `pg_net`، `http`، `vault`، `pg_graphql` نیستند؛ ساختِ نقش‌های Supabase با کاربرِ مدیریت‌شده **نامعلوم** |
| ورود و رمزِ اعضا | هشِ bcryptِ `auth.users` دست‌نخورده منتقل می‌شود (در آزمون ثابت شد) | باید سیستمِ ورودِ جدید هشِ bcrypt را بپذیرد؛ شدنی ولی ساختنی |
| ریسکِ مهاجرت | کم: همان dump، همان ترتیبِ رسمی، اسکریپتِ آزموده | زیاد: بازنویسیِ لایهٔ داده و امنیت، هم‌زمان با قطعی |
| نگهداری | **با ما**: به‌روزرسانیِ Docker/سیستم‌عامل، گواهی (Caddy خودکار)، بکاپ، پایش | Postgres با لیارا؛ بقیه (Auth، API) با ما |
| بکاپ | اسنپ‌شاتِ لیارا (کلِ دیسک) + dumpِ منطقی (بخش ۸) | بکاپِ مدیریت‌شدهٔ لیارا برای Postgres |
| BrsApi / کدال | رله روی لیارا → API روی لیارا: داخلی و سریع‌تر از امروز | همان |
| Telegram / Instagram | Edge Functions خاموش؛ تلگرام روی Vercel می‌ماند؛ **instagram-sync جایگزین ندارد** | همان |

### پیشنهاد: **گزینهٔ الف**

دلیل: تنها گزینه‌ای است که قطعی را **بدونِ بازنویسی** و با **حفظِ ورود، نقش‌ها و RLS** برطرف می‌کند. لیارا برای آن **برنامهٔ آمادهٔ Supabase** دارد (`docs.liara.ir/one-click-apps/supabase/quick-start`) که روی یک سرورِ مجازیِ دبیان با Docker مستقر می‌شود. «داشتنِ PostgreSQL» معادلِ داشتنِ Supabase نیست: گزینهٔ ب فقط یکی از هفت سرویسِ مصرف‌شده را می‌دهد.

**هشدارِ امنیتیِ برنامهٔ آماده / پیش‌فرضِ upstream** — بدونِ این بسته قابلِ‌قبول نیست:
- pooler روی `0.0.0.0:5432` و `0.0.0.0:6543`، و gateway روی `http://IP:8000` (بدونِ TLS) منتشر می‌شوند. Docker قوانینِ iptables خودش را می‌نویسد، پس **ufw این‌ها را پنهان نمی‌کند** (همان یافتهٔ Codex دربارهٔ باز بودنِ پورت روی همهٔ رابط‌ها).
- Caddyِ upstream، **Studio** (کنترلِ کاملِ دیتابیس) را فقط پشتِ یک رمزِ مشترک روی اینترنت می‌گذارد.
- `scripts/selfhost/docker-compose.portfolio.yml` و `Caddyfile` هر سه را می‌بندند؛ `preflight-vps.sh` و `healthcheck.sh` بسته بودنشان را **می‌سنجند**.

## ۶. قدمِ صفر، پیش از هر خرید: آیا بکاپ ممکن است؟

محدودیتِ ۴۰۲ روی API است؛ اینکه **اتصالِ مستقیمِ Postgres** هم بسته شده یا نه **نامعلوم** است. روی لپ‌تاپ (رمز را فقط خودتان و مخفی وارد کنید):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup-production.ps1
```

- **اگر PASS شد:** داده در دسترس است؛ ادامهٔ بخش ۷.
- **اگر اتصال رد شد:** تنها راهِ بیرون‌آوردنِ داده، رفعِ محدودیت از سمتِ Supabase است (پرداخت یا تیکتِ پشتیبانی). خروجیِ منطقی از راهِ MCP قبلاً عمداً رد شده (وفاداری و حجم) و فقط با تأییدِ جدا بررسی می‌شود.

## ۷. راهنمای اجرا (هر مرحله تأییدِ جدا دارد)

**الف — آماده‌سازیِ سرور (پس از خرید)**
1. کلیدِ SSH را در کنسول اضافه کنید؛ ورود با رمز خاموش.
2. میرورِ Docker: `docs.liara.ir/mirrors/docker` (`https://docker-mirror.liara.ir`).
3. در `/opt/supabase-project`: پوشهٔ `portfolio/` بسازید و `Caddyfile` را در آن، و `docker-compose.portfolio.yml` و `docker-compose.caddy.yml` را کنارِ `docker-compose.yml` بگذارید.
4. در `.env`: `PROXY_DOMAIN`، `API_EXTERNAL_URL=https://<api>/auth/v1`، `SUPABASE_PUBLIC_URL=https://<api>`، `SITE_URL=https://arashsafari.ir`، `ADDITIONAL_REDIRECT_URLS`، و SMTP برای ایمیلِ بازیابیِ رمز (بند ۹). کلیدها با `sh utils/generate-keys.sh --update-env` روی خودِ سرور ساخته می‌شوند؛ **هیچ کلیدی در چت یا مخزن نمی‌آید**.
5. `docker compose -f docker-compose.yml -f docker-compose.caddy.yml -f docker-compose.portfolio.yml up -d`
6. `sudo bash scripts/selfhost/preflight-vps.sh` → باید **قبول** بدهد (فقط 22/80/443 عمومی).

**ب — تمرینِ بازگردانی**
1. پوشهٔ بکاپِ بخش ۶ را با `scp` به `/root/restore/prod-<STAMP>` (mode 700) ببرید.
2. `sudo bash scripts/selfhost/restore-to-selfhost.sh /root/restore/prod-<STAMP>` → فقط **PASS** قبول است (PARTIAL یا COMPARE-PENDING قبول نیست). اسکریپت روی مقصدِ غیرتازه اجرا نمی‌شود و کارهای cronِ ابری را خاموش می‌کند.
3. از لپ‌تاپ: `SELFHOST_URL=https://<api> SELFHOST_ANON_KEY=<کلیدِ عمومیِ تازه> bash scripts/selfhost/healthcheck.sh` → **سالم**.
4. یک Preview در Vercel با متغیرهای **فقط Preview** به آدرسِ جدید؛ آرش با حسابِ خودش وارد شود، صفحه‌های بازار و ادمین را ببیند.

**ج — انتقال (فقط با تأییدِ آرش)**
1. اسنپ‌شاتِ سرور.
2. متغیرها: Vercel Production → `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY`؛ رلهٔ لیارا → `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`. سپس redeploy هر دو.
3. `healthcheck.sh` دوباره؛ لاگِ رله: نوشتنِ موفقِ `ir_market_snapshots`؛ ورودِ آرش.
4. پرکردنِ جای خالیِ ۲۱ سپتامبر تا انتقال با بک‌فیل — بستهٔ جدا (قواعدِ `iran-market-data`).

**د — بازگشت**
- تا وقتی Supabaseِ ابری ۴۰۲ است، «بازگشت به ابر» یعنی بازگشت به قطعی؛ پس بازگشتِ واقعی = **برگرداندنِ اسنپ‌شاتِ سرور** یا بازگردانیِ دوباره روی استکِ تازه.
- اگر ابر دوباره فعال شد و بازگشت لازم بود: همان متغیرهای قبلی در Vercel و رله. **هر چه پس از انتقال روی سرورِ جدید نوشته شده، در ابر نیست** — پیش از بازگشت باید با همین ابزار از سرورِ جدید بکاپ گرفت.

## ۹. محدودیت‌های انتقال — صریح

- **نشست‌ها:** کلیدِ JWT تازه است؛ هر دو عضو یک بار دوباره وارد می‌شوند. رمزها **عوض نمی‌شوند**.
- **ایمیلِ Auth (تأیید و بازیابیِ رمز):** GoTrue به SMTP نیاز دارد. پورتِ 25 روی سرورِ لیارا بسته است (`docs.liara.ir/iaas/details/limitations`). گزینه‌ها: سرویسِ ایمیلِ لیارا یا SMTPِ بیرونی روی 465/587. دسترس‌پذیریِ SMTPِ Resend از IPِ ایرانی **نامعلوم**.
- **instagram-sync:** فقط در پروژهٔ ابری است، سورسش در مخزن نیست و از ایران به اینستاگرام نمی‌رسد → **از کار می‌افتد**.
- **telegram-sync (Edge، هر ۳۰ دقیقه):** خاموش می‌شود؛ نسخهٔ Vercel (`/api/cron/telegram-sync`، روزانه) می‌ماند. فاصلهٔ همگام‌سازی از ۳۰ دقیقه به روزانه می‌رسد مگر زمان‌بندیِ Vercel عوض شود.
- **داشبوردِ Supabase** (لاگ، advisor، بکاپِ خودکار) دیگر نیست؛ Studio فقط از تونلِ SSH.
- **نسخهٔ `pg_dump`:** CLIِ Supabase dump را با Postgres 17 می‌گیرد؛ مقصد هم ۱۷ است. تمرینِ بازگردانیِ واقعی روی سرورِ لیارا هنوز **انجام نشده**.
