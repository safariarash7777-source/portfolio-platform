# انتشار: توقفِ نوشتنِ بخش‌های بی‌خواننده در `ir_market_history`

> **دامنه — عمداً باریک.** این بسته فقط **نوشتن** را می‌ایستاند. هیچ ردیفی حذف
> نمی‌شود، هیچ `retention`ای عوض نمی‌شود، هیچ `VACUUM`ی اجرا نمی‌شود.
> **حجمِ امروزِ جدول کم نمی‌شود** — فقط رشدِ آینده محدود می‌شود. پاک‌سازی بستهٔ
> جداگانه‌ای است با دروازه‌های خودش (هفت گیتِ آرشیوِ سندِ #119).

## چرا

اندازه‌گیریِ فقط‌خواندنیِ Production — **۱۴۰۵/۰۶/۲۲ (۲۰۲۶-۰۹-۱۳)**:

| بخش | ردیف | ردیفِ ۲۴ ساعت | حجمِ payload | خوانده می‌شود؟ |
|---|---:|---:|---:|---|
| `stocks` | ۲٬۵۷۱ | ۴۰ | **۳۰۵ MB** | ❌ |
| `funds` | ۲٬۵۷۱ | ۴۰ | **۱۳۸ MB** | ❌ |
| `gold` | ۲٬۶۱۲ | ۴۰ | ۳٬۶۵۸ kB | ✅ |
| `currency` | ۲٬۶۱۲ | ۴۰ | ۳٬۰۳۳ kB | ✅ |

**۴۴۳ MB از ۴۵۰ MB — یعنی ۹۸.۵٪ — هرگز خوانده نشده.** هر چهار بخش دقیقاً
۴۰ نمونه در ۲۴ ساعت گرفتند، پس این رشدِ پایدار است نه یک جهش.

## مصرف‌کننده‌ها — بازبینی‌شده روی `main`ِ امروز، نه روی یادداشتِ قدیمی

```
grep -rn "ir_market_history" --include=*.ts --include=*.tsx app lib components
```

تنها خوانندهٔ داده `lib/core/trend.ts:86` است و دقیقاً این را می‌خواهد:

```
section: "in.(gold,currency)"      # هدف‌ها: gold/IR_GOLD_18K و currency/USD
```

بقیهٔ ارجاع‌ها کامنت‌اند (`app/market/page.tsx`، `TrendChart.tsx`،
`GoldUsdTrend.tsx`، `lib/desk/sources.ts`).

**`ir_market_snapshots` جدولِ دیگری است** — تابلوی زنده، صفحهٔ صندوق،
`symbol-detail`، رادار و میز همه از آن می‌خوانند. این تغییر لمسش نمی‌کند.

پس پیش‌فرضِ `gold,currency` **هیچ مصرف‌کننده‌ای را قطع نمی‌کند**.

## اجرا

۱. رله را با این کد مستقر کن. **هیچ متغیرِ محیطی‌ای لازم نیست** — پیش‌فرض
   `gold,currency` است.
۲. بلافاصله `GET /debug` را ببین:
   - `historySections.written` باید `["gold","currency"]` باشد.
   - `historySections.missing` باید **خالی** باشد. اگر نبود، یعنی منبع آن بخش
     را نداده و مسئله جای دیگری است — این حالت دیگر بی‌صدا نیست.

## شاهدِ «قبل/بعد» — همان پرس‌وجو، ۲۴ ساعت بعد

```sql
select section,
       count(*) filter (where captured_at >= now() - interval '24 hours') as rows_24h,
       max(captured_at) as newest
from ir_market_history group by section order by section;
```

پذیرش:

| بخش | انتظار پس از ۲۴ ساعت |
|---|---|
| `stocks`, `funds` | `rows_24h` = **۰** · `newest` باید در گذشته **ثابت** بماند |
| `gold`, `currency` | `rows_24h` ≈ **۴۰** · `newest` تازه |

⚠️ اگر `gold`/`currency` هم صفر شد، مسئله این تغییر نیست — رله اصلاً داده
نمی‌فرستد. آن را با `historySections.missing` و `/debug` دنبال کن.

و سلامتِ مسیرهای لازم:

- `/market` → بخشِ «روند طلا و دلار» باید همچنان نمودار بدهد (تنها مصرف‌کننده).
- صفحهٔ صندوق و تابلوی بازار → از `ir_market_snapshots` می‌خوانند، بی‌ربط.

## بازگشت

```
IR_HISTORY_SECTIONS=gold,currency,funds,stocks
```

یک متغیرِ محیطی و یک ری‌استارت. **دیتابیس دست‌نخورده است**، پس بازگشت بی‌هزینه
است و بکاپ لازم ندارد.
