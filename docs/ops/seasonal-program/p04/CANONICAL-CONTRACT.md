## قرارداد موجود — VERIFIED از کد

| مفهوم | منبع یگانه | معنای آن |
|---|---|---|
| هویت مالک | نشست Supabase و UUID همان حساب | `user_id` از بدنه درخواست پذیرفته نمی‌شود |
| تصویر مالی ثبت‌شده | `member_holding_versions` | نسخه مشترک دارایی و بدهی، append-only |
| اقلام دارایی | `member_holding_positions` | `version_id` + `position_key`؛ نسخه جدید محتوا را نگه می‌دارد |
| بدهی قطعی | `member_debt_positions` | در همان نسخه مالی؛ تعهد احتمالی بدهی قطعی نیست |
| هدف عضو | `portfolio_versions` | مدل هدف، نه موجودی واقعی |
| مرجع آرش | `intel_reference_*` | مرجع مستقل از دارایی خصوصی عضو |
| رضایت مشاور | consultation relationship/revocation فعلی | admin/نقش Telegram به‌تنهایی مجوز نیست |

اقلام موجود: نماد یا عنوان دستی (دقیقاً یکی)، کلاس دارایی، مقدار، واحد مقدار، تاریخ وضعیت، هزینه مبنا، عنوان، سهم مالکیت، روش ارزش‌گذاری `market/declared/unpriced`، ارزش اظهارشده، منبع/تاریخ/وضعیت ارزش. قیمت بازار دارای مبلغ تومان، واحد مقدار، منبع و زمان است. مبلغ اظهارشده «کل قلم قبل از اعمال مالکیت» است؛ مثلاً 200 میلیون تومان با مالکیت 50٪، 100 میلیون ارزش متعلق به عضو دارد. قیمت و مالکیت فقط یک‌بار اعمال می‌شوند.

`POST /api/portfolio/holdings`: بدنه `{positions, base_version, client_token, note?}`؛ `POST /api/portfolio/debts`: `{debts, base_version, client_token}`. هر درخواست فهرست کامل همان سمت تصویر را جایگزین نسخه‌ای می‌کند و سمت دیگر از نسخه پیشین کپی می‌شود؛ patch تک‌ردیفی نیست. RPCهای موجود `record_member_holdings` و `record_member_debts` حفظ می‌شوند. نتیجه موفق نسخه جدید 201 و retry همان درخواست 200/reused؛ ورودی نامعتبر 400، بدون نشست 401، منع 403، پایه stale یا token با محتوای متفاوت 409، خرابی Auth/ذخیره 503 است. retry نباید token تازه بسازد. تعارض نباید ورودی عضو را پاک کند یا خودکار overwrite کند.

خواندن موجود server-side از `loadPortfolioSnapshot(versionId?)` و `loadVersionDebts(versionId)` است؛ انتخاب نسخه بیگانه معتبر نیست. `loadAdvisorBalanceSheet` همان RPC `consultation_balance_sheet` با گیت رضایت فعلی را مصرف می‌کند. endpoint عمومی GET سبد یا API import در مبنا وجود ندارد؛ آدرس آینده را P05 نباید عملیاتی فرض کند.

پول داخلی عدد صحیح امن تومان است؛ ورودی اظهارشده/بدهی با واحد صریح `IRR/IRT` نرمال می‌شود؛ ریال مضرب 10 لازم است، گردکردن حدسی مجاز نیست. `cost_basis` فعلی صریحاً تومان است؛ import ریالی آن باید قبل از همین مرز تبدیل شود. واحد مقدار مستقل از واحد پول است. داده ناموجود null است؛ خالی‌بودن نسخه ثبت‌شده با فقدان نسخه یا خطای خواندن یکسان نیست.

## ترازنامه و سبد سرمایه‌گذاری

ترازنامه کل: همه دارایی‌ها و بدهی‌های همان نسخه؛ خالص = دارایی منهای بدهی. خالص منفی معتبر است. `buildBalanceSheet` در پوشش ناقص ممکن است subtotal و اختلاف آن با بدهی را برگرداند و `partial=true` بگذارد؛ مصرف‌کننده حق ندارد آن را خالص کامل معرفی کند. تخمین نیز از ارزش معتبر جدا علامت دارد.

سبد قابل تخصیص: زیرمجموعه صریح و تأییدشده دارایی‌ها، با وجه نقد مربوط به همان دامنه. خانه مصرفی، بدهی یا همه ثروت خودکار مخرج وزن نیست. موتور فعلی `compareHoldingsToTarget` همه positions ورودی را جمع می‌کند و metadata مخرج ندارد؛ تا قرارداد انتخاب دامنه اجرا و پذیرفته نشده، خروجی فعلی شاهد پذیرش مخرج P06 نیست.

افزونه پیشنهادی همان مدل موجود: حساب، کاربرد دارایی و قابلیت تخصیص، نقدشوندگی، `memberConfirmedAt`، provenance ورود و رسید انتقال. نام ستون/شماره migration فعلاً تثبیت نشده. اقلام نامشخص از پیش‌نمایش حذف یا سرمایه‌گذاری فرض نشوند؛ محاسبه قطعی باید با علت متوقف شود. خروجی انتخاب دامنه باید `holdingVersionId`، شناسه‌های اقلام منتخب، نوع مخرج، نسخه قواعد انتخاب، تأیید عضو و وضعیت پوشش را حمل کند. این metadata سبد دارایی یا دفتر نسخه دوم نیست.

## مرز P05 و P07/P06

P05 شناسه miniapp را به UUID همان مالک و `position_key` نگاشت می‌کند؛ account linking به‌تنهایی انتقال دارایی نیست. preview اختلاف با نسخه جاری، تأیید عضو، commit اتمیک همان دفتر و رسید counts/reconciliation لازم‌اند؛ پس از پذیرش نوشتن قدیمی باید متوقف شود. اصل فایل/داده محدود و محفوظ، rollback از طریق نسخه اصلاحی یا بازگرداندن مسیر نوشتن با گیت انسانی؛ حذف تاریخچه یا dual-write دائمی مجاز نیست.

P06 همان research version و publication.v1 در P07 را مصرف می‌کند. نوع اقدام، اندازه، مبنای درصد، افق، مخاطب، زمان اثر/انقضا، شروط، تأییدکننده، نسخه قبلی/جایگزین و علت اصلاح لازم‌اند. «درصد فروش موقعیت» با «وزن هدف» و «درصد کل ثروت» جداست؛ ابهام به آرش برمی‌گردد. پیشنهاد/ثبت مشاهده، دارایی واقعی را تغییر نمی‌دهد. آستانه و گروه‌بندی تجاری باز می‌مانند.

## جریان نقد و عملکرد

وجود `transactions` یا تابع `computePerformance` اثبات پوشش نیست. تابع موجود خرید/فروش را جریان بیرونی نمی‌شمارد و واریز/برداشت را جدا می‌کند، اما درصد آن نسبت به ارزش آغاز + واریز است؛ نباید بدون تصمیم روش به‌عنوان TWR/MWR نمایش داده شود. دفتر رویداد متصل به نسخه/حساب، provenance اظهار عضو، مقدار/زمان/واحد، ارتباط دو پای انتقال و وضعیت completeness هنوز شکاف است. انتقال داخلی درآمد/هزینه نیست. ثبت «انجام دادم» اثبات کارگزاری نیست. نمودار بازده تا دو ارزش معتبر، پوشش کامل جریان و روش مصوب خاموش بماند؛ تغییر ارزش ثبت‌شده با بازده متفاوت است.

هیچ مبلغ خصوصی به LLM، شریک یا گروه Telegram منتقل نمی‌شود. قیمت زنده/تازگی و واحد از P02، دسترسی/UUID از P01؛ هیچ SLA یا داده واقعی در این قرارداد اختراع نشده است.
