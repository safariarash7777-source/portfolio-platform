# تسک توسعه‌دهنده: کامل‌کردن مسیر دادهٔ بازار پس از انتقال لیارا

گزارش مبنا: `REPORT.fa.md`، تاریخ ۱ اکتبر ۲۰۲۶. نسخهٔ بررسی‌شدهٔ Production: `51fd0661d48d791ce8758a87828a81ce72cac6df`. ابتدا تغییرات جدید main را بررسی کنید؛ این متن مجوز ادغام کورکورانهٔ شاخه‌های دیگر نیست.

## هدف

سایت اصلی روی Vercel بماند، داده را از لیارا بخواند، صفحهٔ باز طبق cadence واقعی به‌روز شود، همهٔ داده‌های موجود بدون قطع بی‌صدای ۱۰۰۰ردیفی خوانده شوند و شکاف‌های تاریخی با وضعیت مشخص نمایش/ترمیم شوند. سلامت اتصال با کامل‌بودن پوشش اشتباه گرفته نشود.

## بستهٔ ۱: نمایش و خواندن — اولویت P0

1. برای تابلوی سهام و صندوق‌ها refresh کنترل‌شده ایجاد کنید. interval با چرخهٔ پنج‌دقیقه‌ای رله هماهنگ، هنگام مخفی‌بودن صفحه کنترل‌شده و دارای جلوگیری از درخواست هم‌زمان باشد. ساعت freshness در صفحهٔ باز جلو برود. درخواست UI فقط API سایت/دیتابیس را بخواند؛ به BrsApi وصل نشود.
2. در `getHistorySymbols`، distinct نمادها را با pagination پایدار یا RPC خواندنی محدود زیر RLS بخوانید. دادهٔ اسکن‌شدهٔ ۳۰روز با فهرست SQL کامل تطبیق داده شود؛ محدودیت ۱۰۰۰ ردیف در تست شبیه‌سازی شود. query بدون order پایدار پذیرفته نیست.
3. `fundamentalData.fetchCodal` را برای ن-۱۰ و ن-۳۰ صفحه‌بندی کنید. بودجهٔ query، سقف کلی، ordering پایدار و وضعیت پوشش ناقص روشن باشد. صرف افزایش limit یا max-rows جای اصلاح خواننده را نگیرد.
4. error/timeout/table-missing/empty واقعی را در diagnostic تفکیک کنید. هر خطای HTTP نباید «هیچ داده‌ای ثبت نشده» نمایش داده شود. دادهٔ کهنه با تاریخ و برچسب کهنه نگه داشته شود.
5. Production و Preview را با مقصد مشخص بررسی کنید. دو alias عمومی لیارا در حال حاضر فقط Production هستند؛ Previewهای جدید ممکن است legacy Supabase را بخوانند. هیچ service-role key در bundle عمومی قرار نگیرد.

## بستهٔ ۲: انتظار و کارایی — اولویت P1

- `Promise.all` مشترک در `/api/market` و صفحهٔ بازار را طوری بازطراحی کنید که timeout منبع جهانی، دادهٔ سالم ایران را متوقف نکند. timeout هر منبع و loading مرورگر محدود باشد. نتیجهٔ موفق هر منبع حفظ شود.
- بانک داده را از انتظار برای scan سنگین میانگین حجم و همهٔ YoYها جدا کنید؛ cache/aggregation خواندنی با محدودهٔ مشخص یا progressive rendering به کار رود. ابتدا زمان cold/warm و p95 اندازه‌گیری شود؛ زمان یک نمونهٔ ۲۶٫۴ثانیه‌ای را p95 اعلام نکنید.
- cache، timestamp دریافت و تاریخ واقعی منبع را جدا نمایش دهید. بسته‌بودن تابلو را از قطع ارتباط و از دادهٔ کهنه تفکیک کنید.

## بستهٔ ۳: ترمیم تاریخچه — برنامهٔ محدود، قبل از اجرا قابل بازبینی

- ماتریس موجود بودن روزهای رسمی برای هر نماد اصلی بسازید. فاصلهٔ ۲۳ تا ۲۹ سپتامبر برای بیشتر نمادها پوشش ندارد؛ در لیارا فقط برای یک نماد در چند روز این بازه ردیف دیده شد.
- `state.done` اولیهٔ candle backfill نباید بازبینی فاصلهٔ جدید را متوقف کند. state ترمیم بازه/روز مستقل و قابل resume باشد.
- فقط endpoint کاتالوگ رسمی، سری type=2 و واحدهای همان سری استفاده شود. زیرنماد رقم‌دار، حق‌تقدم و نماد فاقد قابلیت مربوط، مطابق قواعد موجود فیلتر شوند.
- قبل از فعال‌سازی، تعداد درخواست مورد نیاز، سهمیهٔ روزانه و تعداد روز تکمیل محاسبه شود. فاصلهٔ حداقل ۵۰ms با صف موجود ۱۰۰ms حفظ شود؛ فرایند دوم با همان کلید ساخته نشود.
- درج append-only با ignore-duplicates و کلید یکتا؛ اجرای دوم نباید ردیف جدید تکراری بسازد. هیچ UPDATE/DELETE روی `symbol_history` یا `codal_reports` انجام نشود.
- دادهٔ داخل‌روزی طلا/ارزِ ثبت‌نشده فقط اگر منبع رسمی همان تاریخ/بسامد را دارد قابل بازیابی است؛ تخمین، درون‌یابی یا تکثیر قیمت امروز ممنوع.

## بستهٔ ۴: پوشش داده

- NAV: ۲۵ مورد از ۳۳۳ صندوق و blacklist فعال ۳۰۸ صندوق بررسی شود. blacklist خودکار پاک نشود. دلیل هر مورد، تاریخ NAV، فعال‌بودن ابزار و اعتبار payload مشخص و cache پس از restart بررسی شود. نقص پوشش با حباب صفر پنهان نشود.
- بورس کالا: `ime_certificate_history` و `ime_physical_trades` قبلاً هم در مبدأ نبودند. migration مربوط با RLS/گرنت، بکاپ و restore آزمایشی و پذیرش read/write اجرا شود. رلهٔ فعلی پیام missing phase19 دارد.
- کدال: failureهای parser از خطای شبکه جدا و با report-kind شمارش شوند؛ نقش captured_at و published_at تفکیک شود. کامل‌بودن feed معادل parsedشدن تمام صورت‌های مالی نیست.
- کلید سمت سرور Vercel، cron، SMTP و بکاپ تازه به عنوان تسک‌های زیرساخت مستقل پیگیری شوند. برای رفع تابلوی عمومی، دسترسی RLS مهمان را گسترش ندهید.

## معیار پذیرش نهایی

1. روی آدرس اصلی و یک Preview مشخص، مقصد داده، deployment و تاریخ نسخه ثبت شود.
2. صفحهٔ سهام/صندوق باز بماند و stamp آن در دو چرخهٔ واقعی جلو برود؛ فیلتر/مرتب‌سازی کاربر حفظ شود.
3. با منبع جهانی کند/خراب، ایران قابل نمایش باشد؛ با دیتابیس کند/خراب، خطا یا دادهٔ کهنهٔ برچسب‌خورده نمایش داده شود و loading بی‌انتها نباشد.
4. فهرست نمادها و پوشش خواندن بنیادی با SQL همان دامنه برابر باشد؛ بیش از ۱۰۰۰ ردیف و گم‌شدن یک صفحه در تست معنی‌دار پوشش داده شود.
5. coverage روزهای تاریخی قبل/بعد ارائه شود؛ no-trade/no-data/unsupported از gap فنی جدا باشد. یک نماد ترمیم‌شده، تکمیل کل بازار محسوب نشود.
6. شناسه‌های اصلی منتقل‌شده حفظ شوند؛ تست idempotency ترمیم و restore لازم موفق باشد.
7. نقش مهمان/عضو/ادمین با حساب آزمایشی مجاز جدا پذیرفته شود. کلید محرمانه، رکورد کاربران یا عدد ساختگی در artifact عمومی نباشد.
8. CI مناسب و build پاس؛ شاهد مرورگر Production و آمار latency/coverage، بدون credential، تحویل شود.

تحویل را با یک PR بزرگ برای همهٔ موارد انجام ندهید؛ بسته‌های خواندن/نمایش، کارایی، ترمیم و schema را جدا و با مرز پذیرش روشن پیش ببرید.
