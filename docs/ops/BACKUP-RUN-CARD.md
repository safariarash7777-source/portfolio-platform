## ۰. چرا این دروازه هست

سازمانِ Production روی پلنِ **رایگان** است و Supabase برایش بکاپِ خودکار
نمی‌گیرد. تا نقطهٔ بازگشتِ **اثبات‌شده** نداشته باشیم، هیچ migrationی روی
Production اجرا نمی‌شود. این قاعده دور زده نمی‌شود.

**الزام «ویندوز» از هیچ دستوری نیامده.** بررسیِ مستند: `scripts/backup-production.sh`
همان کار را روی هر میزبانِ یونیکسیِ دارای Docker انجام می‌دهد. الزامِ واقعی این
است: **یک اپراتورِ انسانی که رمزِ دیتابیس دستش است، روی ماشینی با Docker.**
ویندوز صرفاً ماشینِ آرش است.

**چرا من نمی‌توانم اجرا کنم:** این کانتینر TCPِ مستقیم به دیتابیس ندارد، Docker
daemon ندارد، و — تعیین‌کننده‌تر — **رمز باید دستِ اپراتور بماند و هرگز وارد چت
نشود.** پس این کار ذاتاً دستِ مالک است، نه یک محدودیتِ ابزاری.

## ۲. دستور

روی **ویندوز** (PowerShell، داخلِ پوشهٔ ریپو):

```powershell
.\scripts\backup-production.ps1
```

روی **مک یا لینوکس**:

```bash
bash scripts/backup-production.sh
```

اسکریپت رشتهٔ اتصال را **می‌پرسد** و آن را:
- روی دیسک نمی‌نویسد
- در تاریخچهٔ شل نمی‌گذارد
- در خروجی چاپ نمی‌کند

> ⚠️ **رشتهٔ اتصال را در چت نگذار.** نه اینجا، نه در هیچ پیامی. اسکریپت خودش
> از تو می‌گیرد.

رشته را از **Supabase Dashboard → پروژه → دکمهٔ Connect → Session pooler**
بردار.
