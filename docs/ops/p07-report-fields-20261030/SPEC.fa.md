مبدأ نهایی برش: PR331/source `4013c7c3e972e6b026e093d8dbf39d9df7776fc1`، شاخه محصول `codex/p07-report-fields-stack-20261030`؛ از prototype ساخته نشده است. نام شاخه پایه از metadata رسمی GitHub خوانده شد: `codex/start-c-feed-coverage-20261029`؛ PR تازه روی همین شاخه stack می‌شود. main `f93dbdce` نیز تطبیق داده شد. ref اولیهٔ محلی مبتنی بر main، PR340/head5edf و PR336/source83 بدون reset/deletion حفظ شدند. اسناد مشترک با هماهنگ‌کننده موجود می‌مانند.

## تطبیق قابلیت موجود

PR315 و `companyReportDiscovery` از قبل جست‌وجوی چندواژه‌ای، ترکیب AND با نوع اطلاعیه و حضور تاریخ ارسال، علت کنارگذاری هر ردیف، شمار علت‌های هم‌پوشان و بازنشانی فیلتر را دارند. این منطق و قرارداد داده تغییر نمی‌کنند. اطلاعیهٔ فیلترشده، شرکتِ پذیرفته‌شده با معیار اقتصادی نیست.

شکاف مشخص: در فهرست فعلی، کاربر نمی‌تواند نوع یا زمان ارسال را از نمایش پنهان/دوباره نمایان کند؛ عنوان/منبع و این دو فیلد همیشه در قالب ثابت‌اند. انتخاب اطلاعات نمایشی بخشی محدود از P07.4 است، نه تکمیل فیلتر اقتصادی یا کل صفحه شرکت.

## برش حداقلی

- دو checkbox نامدار برای نمایش نوع اطلاعیه و زمان ارسال؛ پیش‌فرض همان نمایش فعلی است. چون رابط موجود فهرست است، UI آن را «اطلاعات نمایشی» می‌نامد و به جدول/طرح P14 تبدیل نمی‌کند.
- عنوان و پیوند منبع همیشه ثابت و تحت همان `CodalSourceLink` باقی می‌مانند.
- تاریخ انتشار و پیام نامعلوم آن از PR331 همیشه باقی می‌مانند؛ کنترل «زمان ارسال» فقط قسمت sent-date/time را پنهان می‌کند، نه publication metadata یا هشدارهای کیفیت/پوشش.
- زمان ارسالِ موجود تابع checkbox است؛ اگر تاریخ ارسال همان رکورد نامعلوم باشد، هشدار «زمان ارسال نامعلوم» کنار همان رکورد حتی با checkbox خاموش باقی می‌ماند. شمار کلِ تاریخ‌های ناموجود جای این هشدار رکوردی را نمی‌گیرد.
- پنهان‌کردن فیلد، شرط فیلتر، ردیف‌های نتیجه، شمار/علت کنارگذاری و هشدار تاریخ نامعلوم را تغییر نمی‌دهد. بازنمایانی همان مقدار اصلی را نشان می‌دهد.
- انتخاب فقط state نمایشی همان صفحه است؛ ذخیره حساب، localStorage، endpoint یا درخواست تازه ایجاد نمی‌شود. با تعویض نماد به پیش‌فرض بازمی‌گردد؛ پاسخ دیررس نماد قبلی مجاز نمی‌شود.

محصول فقط `components/symbol/CodalReportsTab.tsx` و آزمون همان فایل؛ اسناد همین پوشه. هماهنگ‌کننده پیش از ویرایش محصول ناحیه state/UI و test را برای این برش رزرو کرد؛ C روی این ناحیه نمی‌نویسد. مبدأ ثابت331 برای حفظ متادیتا، سقف۳۰/۶۰، timeout/loading/error/manual retry آن انتخاب شد. `lib/core/companyReportDiscovery`، `lib/codal-feed`، API، `lib/fundamental`، relay، engine، types، package، SQL و env تغییر نمی‌کنند. PR331 در زمان ممیزی open/head4013 است؛ قابلیت‌های آن ادغام‌شده فرض نمی‌شوند. دو آزمون موجودِ helper و UI در runner فعلی package حاضرند و package نیاز به تغییر ندارد.

## معیار پذیرش و اجرا

۱. پیش از اصلاح، آزمون رفتاری روی همان کامپوننت، نبود کنترل انتخاب نمایش را RED کند. سپس کوچک‌ترین اصلاح.

۲. آزمون ترکیب فیلتر و پنهان/نمایان‌کردن: نتیجه/ترتیب/منبع/علت‌ها و تاریخ نامعلوم ثابت، درخواست فقط همان دریافت اولیه. پاک‌کردن فیلتر مستقل از انتخاب نمایش؛ تعویض نماد انتخاب را به پیش‌فرض برگرداند و داده قدیمی نمایش ندهد.

۳. آزمون‌های مرتبط موجود، lint محدوده، typecheck و اسکن متناسب؛ هیچ تست/تغییر مصنوعی برای منطق از قبل درست ساخته نشود.

۴. Preview پروژه موجود و مشاهدهٔ کنترل‌ها روی فهرست واقعیِ ذخیره‌شده، اگر دسترسی آن برقرار باشد؛ تست با stub فقط شاهد آزمون است، نه پذیرش آنلاین یا تازگی مالی. API جعلی برای دورزدن مانع داده ساخته نمی‌شود. بستن تست/کد از انتشار main و پذیرش آرش جداست.

مقادیر غایب null می‌مانند؛ تاریخ ارسال جای انتشار/دوره مالی نیست. هیچ آستانه، امتیاز، محاسبه، مدل، provider refresh، هزینه، سرویس یا DDL تازه وجود ندارد. روش برگشت فقط revert همین برش رابط است.
