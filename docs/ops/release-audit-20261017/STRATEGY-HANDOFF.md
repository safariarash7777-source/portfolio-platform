- خواسته‌های مستقیم آرش: حفظ کار قبلی، سه مسیر مستقل، طراحی ماژولار با هویت فعلی، شخصی‌سازی، انتشار بسته‌های آماده و مصرف متناسب مدل.

- [DECISION-LOG](../../DECISION-LOG.md): تصمیم‌های پذیرفته‌شده؛ پیشنهادهای برنامه قدیمی خودکار تعهد تازه نشده‌اند.
- [COMMAND-CENTER](../../COMMAND-CENTER.md): مالک، نسخه، مانع و اقدام بعدی. [MIGRATION-LEDGER](../../MIGRATION-LEDGER.md) مرجع نصب schema است.
- گزارش چت‌های طراحی و ایجنت، GitHub/CI، Vercel و شواهد اجرا با هم تطبیق داده شدند؛ پیام «انجام شد» به‌تنهایی شاهد انتشار نیست.

## پیشنهاد اجرایی هماهنگ‌کننده

نسخهٔ بعدی را «یک مسیر کامل برای آرش و یک مسیر کامل برای عضو» تعریف کنیم. معیار پایان، کارکرد قابل مشاهده و محفوظ‌ماندن داده است.

۱. تثبیت رفتار سه نمای قابل تعویض و انتقال محدود به میز آرش، سپس خانه عضو؛ API و محاسبه موجود حفظ شوند. معیار: داده واقعی، خطا/کهنگی، موبایل و شخصی‌سازی روشن.
۲. تکمیل مسیر عضو از ورود تا ثبت/خواندن/نسخه دوم و اقدام بعدی؛ وبینارِ نیازمند انتقال از این عرضه جدا بماند. دفتر خصوصی پژوهش فقط اگر واقعاً جزء نسخه بعدی است قرارداد بگیرد.
۳. تثبیت پژوهش و داده: ارزیابی کیفیت، پوشش معلوم، گزارش شکست و میزبانی مناسب. افزایش تعداد ایجنت یا مدل قوی‌تر به‌تنهایی نتیجه بهتر محسوب نشود.

کارهای معمول این نوبت به سه عامل Sol سپرده شد؛ بازبینی مشترک و انتشار یک هماهنگ‌کننده داشت. آزمون یکسان روی tree یکسان تکرار نشد؛ آزمون تازه برای پذیرش واقعی، گیت نصب و خطای تاریخ دلیل مشخص داشت. سقف تعداد/زمان پژوهش، سقف قطعی توکن نیست.
