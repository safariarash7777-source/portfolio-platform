# P07 — بازتفسیر محدود یک اطلاعیه از آرشیو

این بسته **source candidate** است. SQL نصب نشده؛ هیچ فراخوانی مقصد، دریافت تأمین‌کننده، تغییر نسخه عمومی پارسر یا تغییر دادهٔ سایت انجام نشده است. وضعیت انتشار را هماهنگ‌کننده در COMMAND-CENTER ثبت می‌کند.

## مسئله و رفتار

رکورد قدیمی 11653 مقدارها و مبلغ‌ها را دارد، اما رسید هش بدنه ندارد. آرشیو رسمی با نشانی اطلاعیه، اکسل، نماد و دورهٔ آن منطبق است؛ این انطباق اثبات برابری بایت‌های دریافت قدیمی نیست. ورودی جدید `parseArchivedReport` فقط پس از تطبیق manifest بازبینی‌شده، هش بایت‌ها و دورهٔ داخل جدول، از همان `normalizeN30` استفاده می‌کند. خروجی را فقط همان شیء دست‌نخورده می‌تواند از `insertParsedReport` در حالت صریح بازتفسیر ثبت کند.

`PARSER_VERSION=2` و تمام فراخوان‌های عادی ثابت‌اند. نسخهٔ جدید فقط برای یک اطلاعیه انتخاب می‌شود؛ `existingUrls` و feed/archive/backfill تغییر نمی‌کنند. سطر جدید در همان `codal_reports` قرار می‌گیرد. مبلغ‌ها، مقدارهای خام و نرخ‌های خام قدیمی حفظ می‌شوند؛ واحد مقدار و طبقه‌بندی داخلی/صادراتی/خدمات از شاهد آرشیو تفسیر می‌شوند. نرخ قابل‌نمایش تا احراز مستقل مخرج نرخ همچنان null است.

## قرارداد نوشتن

- ورودی: کل سطرهای تازهٔ همان نماد/نوع/دوره (حداکثر 500)، شناسهٔ مبنا، SHA256 قرارداد canonical جاوااسکریپت، نسخه، اطلاعیه و شناسهٔ درخواست ثابت. `rowHash` در producer بازسنجی می‌شود؛ SQL به هش ارسالی به‌عنوان CAS اتکا ندارد و **کل JSON سطرها** را زیر قفل با پایگاه داده مقایسه می‌کند. بنابراین هش مرور و مقایسهٔ اتمیک دو شاهد جدا هستند.
- `codal_reinterpret_one`: همان نوشتن به جدول موجود؛ INVOKER، بدون SQL پویا، بدون UPDATE/DELETE، نام جدول ثابت. هویت، انتشار، عنوان اصلاحیه، raw قدیمی، تقدم نسخه و عدم تغییر مبلغ را کنترل می‌کند.
- قفل جدول `SHARE ROW EXCLUSIVE` با INSERT عادی هم تعارض دارد. صرف کلید یکتا، مقایسهٔ تازهٔ کل دوره را تضمین نمی‌کند؛ قفل مشورتی و قفل سطر، INSERT نویسندهٔ عادی را نمی‌بندند. این قفل فقط برای تراکنش محدود یک گزارش است و مناسب backfill نیست.
- نقش دارای فقط INSERT حق گرفتن این قفل را ندارد. helper خصوصی `codal_private.reinterpret_lock` صرفاً همین قفل را می‌گیرد: DEFINER، search_path خالی، بدون خواندن/نوشتن یا پارامتر نام جدول؛ EXEC عمومی/anon/authenticated بسته و service_role صریح است. هیچ امتیاز UPDATE/DELETE اضافه نمی‌شود. **پذیرش امنیتی مستقل، مالک helper و غیرexposed بودن schema در مقصد هنوز گیت نصب‌اند.**
- `lock_timeout=1500ms`. `statement_timeout` باید **پیش از شروع statement** حداکثر پنج ثانیه فعال شده باشد؛ نبود آن درخواست را رد می‌کند. SET درون تابع به‌عنوان deadline همان statement معرفی نشده است. این تنظیم مقصد هنوز اجرا نشده؛ پیکربندی محدود عملیاتی را هماهنگ‌کننده تعیین می‌کند.
- درخواست باید تراکنش مستقل باشد؛ پس از تابع کار طولانی یا تراکنش باز نگه داشته نشود. قفل کوتاه همهٔ INSERTهای جدول را موقتاً درگیر می‌کند، نه فقط اطلاعیهٔ انتخابی. busy باید بدون اثر متوقف شود.
- ورودی archive یک attestation بازبینی‌شده است؛ متن دلخواه کاربر یا فایل فاقد منشأ ورودی مجاز عملیاتی نیست. هش فقط تمامیت فایل را ثابت می‌کند، نه اصالت تأمین‌کننده را.

## نتیجه نامعلوم، تکرار و بازگشت

`persistReinterpretation` دقیقاً یک POST سپس GET روی source_url نسخه‌دار دارد. موفقیت فقط با تطبیق کامل payload و شناسه/زمان واقعی دیتابیس اعلام می‌شود. نبودن سطر یا اختلاف، UNKNOWN است؛ هیچ retry خودکار POST وجود ندارد. `readBackReinterpretation` مسیر بازیابی GET-only با همان intent ذخیره‌شده است. SQL برای payload دقیقاً یکسان همان سطر را برمی‌گرداند و برای تصادم متفاوت خطا می‌دهد؛ این idempotency مجوز تکرار کور در پاسخ نامعلوم نیست.

قبل از commit، ROLLBACK تراکنش هیچ سطر جدیدی باقی نمی‌گذارد. پس از commit، `restorePayload` و همان RPC یک **نسخه بالاتر از تفسیر قدیمی** می‌افزایند؛ هیچ نسخه‌ای حذف نمی‌شود. رسید quantity قدیمی به سطر تازه قرض داده نمی‌شود. مقادیر قبلی حفظ می‌شوند و کیفیت مقدار ممکن است صادقانه دوباره نامعلوم شود. نسخهٔ بالاتر صرفاً انتخاب همان اطلاعیه را تغییر می‌دهد؛ قواعد موجود خواننده برای برنده‌بودن اصلاحیهٔ اطلاعیهٔ دیگر حفظ‌اند.

## آزمون و اتصال CI

محلی: 7 آزمون جدید + 9 آزمون producer قبلی PASS، fail/skip صفر؛ typecheck و lint فایل TypeScript PASS. آزمون‌های موجود N10 و خوانندهٔ مقدار و پارسر نیز PASS. فایل‌های relay طبق پیکربندی موجود از ESLint خارج‌اند؛ lint آن‌ها ادعا نمی‌شود. SQL policy validation PASS؛ آزمون grammar و Postgres محلی اجرا نشده‌اند (Python و Docker engine در این میزبان در دسترس نبودند).

آزمون Postgres در `lib/fundamental/codal-reinterpretation.integration.test.ts` فقط با `CI=true` و Postgres مصنوعی loopback:5433 اجرا می‌شود. دیتابیس تازهٔ ثابت می‌سازد و در صورت وجود قبلی آن متوقف می‌شود؛ دادهٔ مقصد یا drop/reuse ندارد. جدول از DDL واقعی پروژه خوانده می‌شود. بایت HTML رسمی است؛ شناسه‌ها، زمان ثبت و transport آزمون **مصنوعی** هستند و شاهد ingestion عملیاتی نیستند.

فرمان پیشنهادی برای هماهنگ‌کننده، در **همان job موجود** پس از نصب psql:

```sh
node node_modules/tsx/dist/cli.mjs --test --test-concurrency=1 lib/fundamental/codal-reinterpretation.integration.test.ts
```

در job کیفیت موجود:

```sh
node --test relay/codal-reinterpretation.test.mjs
```

workflow و package scripts در این بسته ویرایش نشده‌اند. CI مستقل، آزمون واقعی PostgreSQL، build و بازبینی امنیتی هنوز باید روی SHA دقیق انجام شوند. نصب مقصد علاوه بر این‌ها به هویت/backup-restore/خواندن مبنای تازه، تنظیم timeout، مجوز محدود اجرای یک گزارش و تطبیق خواننده/مرورگر نیاز دارد.
