# رانبوکِ تمرینِ خصوصیِ میزِ آرش

> مأموریت: `P2-G3-MEGA-004` · وضعیت: **آماده برای شروع، شروع‌نشده**
>
> این سند مرحلهٔ **بعد** از تأییدِ PR #101 است: کارِ روزانهٔ دستیِ آرش با میز،
> پیش از آنکه هیچ خودکارسازی‌ای ساخته شود.
>
> ⚠️ **این تمرین هنوز اجرا نشده و Gate 3 باز است.** هیچ عددی در این سند
> «نتیجه» نیست؛ همه جای خالیِ اندازه‌گیری‌اند. تنها کسی که می‌تواند تمرین را
> موفق اعلام کند **آرش** است.

---

## ۰) چرا تمرینِ دستی، پیش از خودکارسازی

فرایندی که انسان یک‌بار هم اجرایش نکرده، قابلِ خودکارسازی نیست — چون
نمی‌دانیم چه ورودی‌ای واقعاً لازم است، کجا داده کم می‌آید، و کدام قضاوت
اصلاً قابلِ واگذاری نیست. ده روزِ کاریِ دستی این‌ها را معلوم می‌کند؛ حدس نه.

هدفِ این تمرین **تولیدِ محتوا نیست**. هدف **اندازه‌گیریِ فرایند** است.

---

## ۱) گردشِ کارِ روزانه

هر روزِ کاری، به همین ترتیب:

| # | گام | مقصد | چه چیزی را جواب می‌دهد |
|---|---|---|---|
| ۱ | بازکردنِ میز | `/admin/desk` | نمای کلی |
| ۲ | **اول** سلامت و دادهٔ کهنه | ناحیهٔ «عملیات و سلامت» → لینکِ `/admin/health` | آیا اصلاً می‌شود به بقیهٔ صفحه اعتماد کرد؟ |
| ۳ | تغییرهای مهمِ بازار | ناحیهٔ «امروز» → `/admin/radar`، `/admin/fx` | امروز چه گذشت؟ |
| ۴ | خبر، رخداد، کدال | ناحیهٔ «هوشمندیِ بازار» → `/admin/content`، `/codal` | چه چیزی باید دیده شود؟ |
| ۵ | ثبتِ پیش‌نویسِ **داخلیِ** Daily Brief | بیرونِ سامانه (تا وجودِ جدولش) | جمع‌بندیِ روز |
| ۶ | ثبتِ تغییرِ سناریوها | ناحیهٔ «تصمیم‌ها» → `/admin/notes` | چه فرضی قوی/ضعیف شد؟ |
| ۷ | اثر روی سبدِ مرجع | ناحیهٔ «سبدِ مرجع» | آیا وزنی باید بازبینی شود؟ |
| ۸ | تأیید / اصلاح / ردِ **دستیِ** پیش‌نویس‌ها | `/admin/analyses` | انسان در حلقه |
| ۹ | ثبتِ زمانِ صرف‌شده و اطلاعاتِ غایب | جدولِ بخشِ ۲ | ورودیِ خودِ تمرین |

**گامِ ۲ عمداً اول است.** اگر رله دو روز ساکت باشد، هر برداشتی از گامِ ۳
نادرست است. میز حالا این را پنهان نمی‌کند: هر منبع حالتِ خودش را دارد و یک
منبعِ مرده پشتِ همسایهٔ سالمش گم نمی‌شود.

### قواعدِ سختِ حینِ تمرین

- **هیچ انتشارِ عمومیِ خودکار.** `canPublishBrief()` مسیرِ
  «پیش‌نویسِ داخلی ← منتشرشده» را می‌بندد؛ تأییدِ انسانی اجباری است (`DD-023`).
- **هیچ تحلیلِ ساختگی، آزمایشی یا نمونه** به‌عنوان تحلیلِ واقعی ثبت نمی‌شود.
- **دادهٔ ناموجود `null` می‌ماند** — هرگز عددِ جای‌پرکن.
- ارزش‌گذاری همیشه **بازه + سه سناریو**؛ هرگز قیمتِ هدفِ واحد.
- واژه‌های «سیگنال/خرید/فروش/توصیه/پیشنهاد» در هیچ خروجی‌ای نمی‌آید.

## ۲) اندازه‌گیری‌های اجباری — دفترِ روزانه

هر روز یک ردیف. **خالی‌گذاشتن بهتر از حدس‌زدن است.**

| تاریخ | Brief تولید شد؟ | زمانِ کل (دقیقه) | منابعِ غایب | منابعِ کهنه | تعدادِ اصلاح | نتیجه‌گیری‌های ردشده | تصمیم‌های متأثر | رخدادهای ازدست‌رفته | کارهای پیگیری |
|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | |

تعریف‌ها، تا دو نفر یک‌جور نشمارند:

- **منبعِ غایب** — ردیفی با حالتِ `در دسترس نیست`.
- **منبعِ کهنه** — ردیفی با حالتِ `کهنه`.
- **اصلاح** — جایی که آرش عددی یا برداشتی را پیش از ثبت تغییر داده.
- **نتیجه‌گیریِ ردشده** — پیش‌نویسی که کامل کنار گذاشته شده.
- **رخدادِ ازدست‌رفته** — چیزی که **بعداً** معلوم شد مهم بوده و میز نشانش نداده.
  این مهم‌ترین ستون است: نقصِ پوششِ میز را نشان می‌دهد، نه نقصِ آرش را.

## ۴) میز امروز به کدام پرسش‌ها جواب می‌دهد

از نُه پرسشِ Blueprint، MVP صادقانه این‌ها را پوشش می‌دهد:

| # | پرسش | وضعیت در MVP |
|---|---|---|
| ۱ | امروز چه گذشت؟ | 🟡 **جزئی** — تازگیِ منابع بله؛ روایتِ رویداد نه |
| ۲ | کدام تغییرِ بازار مهم است؟ | 🔴 **خارج از MVP** — نیازمندِ قضاوت، نه شمارش |
| ۳ | کدام داده کهنه/غایب/واقعاً خالی است؟ | 🟢 **کامل** — همان هستهٔ چهارحالتیِ میز |
| ۴ | کدام رخداد و گزارشِ کدال توجه می‌خواهد؟ | 🟡 **جزئی** — شمارش و لینک بله؛ اولویت‌بندی نه |
| ۵ | کدام سناریو قوی/ضعیف شد؟ | 🔴 **خارج از MVP** — نیازمندِ `phase20` + فرایندِ دستی |
| ۶ | وضعیتِ سبدِ مرجع؟ | 🟡 **جزئی** — وجود/نبودِ نسخه بله؛ وزن‌ها نه (`D` باز) |
| ۷ | کدام تحلیل بازبینیِ انسانی می‌خواهد؟ | 🟡 **جزئی** — شمارشِ صف بله؛ صفِ عملیاتی نه |
| ۸ | کدام مشتری/محصول اقدام می‌خواهد؟ | 🔴 **خارج از MVP** — عمداً؛ نیازمندِ دادهٔ سطحِ مشتری |
| ۹ | خطِ لولهٔ داده و cronها سالم‌اند؟ | 🟢 **کامل** (پس از `phase21`) |

پرسشِ ۸ عمداً بیرون است: پاسخش دادهٔ سطحِ مشتری می‌خواهد و میز به‌طورِ
ساختاری فقط شمارشِ تجمیعی برمی‌گرداند.

- **دربارهٔ کیفیتِ تحلیل چیزی نمی‌گوید** — دربارهٔ فرایند می‌گوید.
