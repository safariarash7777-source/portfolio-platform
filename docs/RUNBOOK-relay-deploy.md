# استقرار رله — و چرا مسیر خودکارش کار نمی‌کند

> **وضعیت `B-053`:** یکپارچه‌سازیِ GitHub→Liara برای اپِ `arsadata` **هرگز یک
> استقرارِ موفق نداشته**. ۱۵۶ رکوردِ استقرار از ۲۰۲۶-۰۷-۱۶ تا امروز؛ ۱۶ نمونهٔ
> پخش‌شده در کلِ بازه — از **اولین** رکورد تا آخرین — همگی `failure`.
>
> یعنی این یک **رگرسیون نیست** که بشود با bisect پیدایش کرد. پیکربندی از روزِ
> اول کار نکرده. پس هر نسخه‌ای از رله که تا امروز روی Production رفته، از
> **مسیرِ دیگری** رفته (به احتمال زیاد `liara` CLI از دستگاهِ آرش) و
> **شناسهٔ نسخه‌اش هیچ‌جا ثبت نشده**.

| بررسی | نتیجه |
|---|---|
| آیا artifact قابلِ اجراست؟ | ✅ `node relay/server.mjs` روی `main@1d7e8f1` بالا می‌آید، `/healthz` → `ok` |
| وابستگیِ خارجی؟ | ❌ **هیچ.** `relay/package.json` نه `dependencies` دارد نه `devDependencies`؛ همهٔ importها `node:*` هستند. پس نه `npm ci` لازم است نه lockfile |
| دستورِ اجرا | `node server.mjs` (از `relay/package.json`) |
| پورت و پلتفرم | `relay/liara.json`: `platform: node`، `port: 3400` |
| نسخهٔ Node | `relay/package.json` → `>=18`؛ ⚠️ **ریشهٔ مخزن** `>=20` می‌خواهد و اپِ Next است (`next start`) |

⚠️ **آنچه اثبات **نشده**:** تنظیماتِ واقعیِ کنسول — مخزن، branch، پوشهٔ build،
platform، دستورِ start، پورت و نسخهٔ Node. فایل‌های بالا **نیت** مخزن‌اند، نه
پیکربندیِ پلتفرم. تا وقتی لاگِ بیلد خوانده نشود، **هیچ علتی قطعی نیست** —
از جمله این فرضیه که بیلد از ریشهٔ مخزن اجرا می‌شود.

## پیش‌پروازِ اجباری — پیش از هر استقرار

هدف: استقرارِ این نسخه نباید ناخواسته enforcementِ وابسته به `phase28` را
روشن کند. **اندازه‌گیری‌شده روی همان artifact، نه استنتاج از کد:**

```
$ RELAY_TOKEN=… PORT=3499 node relay/server.mjs
$ curl -H "Authorization: Bearer …" localhost:3499/debug
historySections  : {"written": ["gold","currency"], "missing": []}
brsapiLegacy.enforced : false
brsapiClient.enabled  : false
```

هر سه باید همین باشند. اگر `enforced` برابر `true` بود، یعنی
`BRSAPI_BUDGET_ENFORCE_LEGACY` در محیطِ مقصد ست شده — **پیش از استقرار
برش دار**؛ هر دو پرچم صریحاً `=== "1"` می‌خواهند و پیش‌فرضشان خاموش است.

## مسیرِ استقرار

دو راه هست و **هیچ‌کدام نیازی به رفعِ یکپارچه‌سازی ندارد**:

**الف) دستی از دستگاهِ آرش (سریع‌ترین).** از داخلِ پوشهٔ `relay/`، با
`liara` CLI روی همان اپِ `arsadata` مستقر کن. شکلِ دستور را با
`liara deploy --help` تأیید کن — این سند نحوِ CLI را ادعا نمی‌کند، فقط
می‌گوید **پوشهٔ مبدأ باید `relay/` باشد**، نه ریشهٔ مخزن.

**ب) رفعِ یکپارچه‌سازی.** پس از خواندنِ لاگ، در کنسول مسیرِ اپ را روی `relay/`
تنظیم کن. این کار **تغییرِ کد لازم ندارد**.

> در هر دو حالت، نسخهٔ در حالِ اجرای فعلی تا لحظهٔ جایگزینیِ موفق دست‌نخورده
> می‌ماند — رله امروز زنده است و می‌نویسد.

## پذیرش — دو چرخهٔ نوشتن

چرخهٔ تاریخچه هر **۳۰ دقیقه** است، پس دو چرخه ≈ **۶۰ دقیقه** پس از استقرار.

```sql
select section,
       count(*) filter (where captured_at >= now() - interval '70 minutes') as rows_70m,
       max(captured_at) as newest
from ir_market_history group by section order by section;
```

| بخش | انتظار |
|---|---|
| `stocks`, `funds` | `rows_70m = 0` · `newest` **ثابت** روی زمانِ پیش از استقرار |
| `gold`, `currency` | `rows_70m ≥ 2` · `newest` تازه |

و زنده‌بودنِ بقیهٔ مسیرها:

```sql
select updated_at from ir_market_snapshots where key='latest';
```

باید تازه باشد — یعنی تابلوی زنده، صفحهٔ صندوق و `symbol-detail` قطع نشده‌اند.

⚠️ **دادهٔ قبلی حذف نمی‌شود.** این تغییر فقط **نوشتن** را می‌ایستاند؛ حجمِ
امروزِ جدول کم نمی‌شود.

⚠️ دو چرخه **پایداریِ بلندمدت را اثبات نمی‌کند** — فقط می‌گوید تغییر در همان
یک ساعت اثر کرده.
