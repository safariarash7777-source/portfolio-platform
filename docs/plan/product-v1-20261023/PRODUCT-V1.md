# تعریف نسخه اول و تصمیم قابلیت‌ها
تاریخ: ۲۰۲۶-۱۰-۲۳؛ مخاطب: عضو فعلی مشاوره، آرش صفری، مجری محصول. مبنا: برنامه‌ای که مالک صریحاً اجرای آن را درخواست کرده است. «اکنون» به معنی دامنه نسخه اول است، نه انتشار هم‌زمان همه قابلیت‌ها.

## نتیجه مورد انتظار
عضو بداند چه دارد، چه تعهدی دارد و قدم بعدی او چیست. آرش بتواند با همان پرونده، توصیه متناسب را بررسی و تأیید کند؛ نتیجه و موعد پیگیری برای هر دو روشن باشد.
خانه عمومی هویت، رسانه و راه خدمات را حفظ می‌کند. سه فضای کاری خصوصی عضو، مشاور و پژوهش یک مرجع مالی و یک نسخه توصیه دارند. آمار بازدید یا تعداد نمودار شاخص موفقیت این نسخه نیست.

## رفتار سه فضا
- عضو: تصویر مالی با میزان کامل‌بودن، اقساط نزدیک، بودجه/هدف و اقدام بعدی؛ اعداد مالی فرضی نمایش داده نشوند.
- مشاور: فیلتر → پرونده → بررسی نقص و تناسب → پیش‌نویس → تأیید → انتشار → پیگیری. گروه‌بندی کاربر مجوز مشاهده یا گواه تناسب نیست.
- پژوهش: سند → کنترل منبع/زمان/واحد → محاسبه و فرض → تحلیل خصوصی → بررسی آرش. خروجی مدل زبانی به‌تنهایی عدد مالی معتبر یا توصیه منتشرشده نیست.

## حداقل قرارداد مشترک (طرح؛ نه API ساخته‌شده)
- مدل مالی موجود مرجع است؛ تومان صحیح، تبدیل ریال فقط در مرز ورود، تاریخ روز مالی بدون جابه‌جایی منطقه زمانی، نمایش جلالی.
- مقدار و تاریخ نامعلوم nullable؛ پوشش unknown/partial/complete. فقط داده کافی اجازه جمع قطعی می‌دهد.
- انتقال داخلی در مجموع محدوده درآمد/هزینه نیست؛ قسط برنامه‌ریزی‌شده پرداخت واقعی نیست؛ هدف مالی با وزن هدف سرمایه‌گذاری یکی نیست.
- رابطه عضو/مشاور قابل لغو است؛ یادداشت داخلی و محتوای تحویل‌شده جدا. مجوز در خواندن/نوشتن و اعلان کنترل شود.
- توصیه: شناسه و نسخه، عضو/مخاطب مجاز، نسخه پرونده مبنا، شواهد و دلیل، محدودیت، افق/موعد بازبینی، تأییدکننده/زمان، وضعیت انتشار.
- وضعیت توصیه: پیش‌نویس → آماده بازبینی → تأیید آرش → منتشرشده → جایگزین‌شده/منقضی. تغییر محتوای تأییدشده نسخه تازه و تأیید تازه می‌خواهد. تغییر مادی پرونده مبنا پیش از انتشار، بازبینی مجدد می‌خواهد.
- مشاهده و اعلام اقدام عضو رویدادهای مستقل‌اند؛ اعلام عضو تأیید معامله نزد کارگزاری نیست. نسخه جدید تاریخچه قبلی را پاک نمی‌کند.
- مشاهده بازار: منبع، زمان مشاهده/انتشار در صورت وجود، دوره، واحد، نوع ابزار/واحد صندوق، تعریف شاخص و وضعیت کیفیت. داده متناقض به بررسی برود.
- تلگرام رابط همین شناسه عضو و نسخه توصیه است. اعلان صف‌شده پیش از ارسال دوباره از نظر مجوز و اعتبار نسخه کنترل شود.

در این تحویل endpoint، migration و schema جدید ایجاد نمی‌شود. مجری قبل از طراحی API جدید، قراردادها و نام‌های موجود را تطبیق دهد.

## بسته‌ها و وابستگی
P1 بستن جریان نقد موجود؛ P2 بودجه/هدف و تکمیل داشبورد؛ P3 پرونده/فیلتر و توصیه تأییدشده؛ P4 مقایسه صندوق و پژوهش محدود؛ P5 تلگرام. طراحی سه مسیر از P1 همراه کار است. پژوهش خصوصی آماده می‌شود اما خروجی شخصی پیش از P3 منتشر نمی‌شود. بسته مستقل UI می‌تواند پیش برود؛ مانع زیرساخت مجوز ادعای تحویل مالی نیست.

## پذیرش نسخه اول
دو عضو مصنوعی مجزا؛ لغو دسترسی مشاور؛ رد انتشار بدون تأیید؛ حفظ نسخه و اصلاحات؛ انتقال حساب بدون درآمد ساختگی؛ retry بدون ثبت تکراری؛ نتیجه نامعلوم بدون replay کور؛ موبایل ۳۹۰ و ۳۲۰ و دسکتاپ؛ بارگذاری، خالی، ناقص، کهنه، خطا؛ مشاهده نسخه در سایت و تلگرام؛ پذیرش جداگانه آرش. زمان پایان و درصد پیشرفت بدون شاهد تعیین نمی‌شود.
