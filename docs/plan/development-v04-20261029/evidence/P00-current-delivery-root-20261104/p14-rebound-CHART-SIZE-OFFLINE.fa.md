# بررسی آفلاین هشدار اندازهٔ نمودار

روی source e9ce72 و همان node_modules موجود، بدون مرورگر/شبکه یا تغییر کد بررسی شد.

## شاهد کد

- `components/symbol/SymbolTabs.tsx:37`: تب اولیه overview است؛ hash لینک مستقیم بنیادی در effect خط۵۹ خوانده می‌شود.
- `SymbolTabs.tsx:136`: همهٔ پنل‌ها mounted هستند و پنل غیرفعال hidden است؛ در اولین mount لینک مستقیم بنیادی نیز این پنل پنهان است.
- MonthlySalesCharts برای نمودارها والد با ارتفاع۲۸۰ و ResponsiveContainer صددرصدی دارد؛ Quarterly/Fundamental نیز ارتفاع مشخص دارند. کمبود همیشگی ارتفاع والد از این کد ثابت نمی‌شود.
- Recharts محلی `lib/component/ResponsiveContainer.js:126` در effect اندازهٔ واقعی getBoundingClientRect را می‌خواند و ResizeObserver نصب می‌کند. خط۱۴۸ با اندازهٔ صفر/صفر هشدار ثبت می‌کند؛ provider در خطوط۴۱–۴۹ تا مثبت‌شدن اندازه، chart child را نمایش نمی‌دهد.
- مقدار اولیهٔ کتابخانه منفی۱ است و شرط هشدار این وضعیت اولیه را مستثنا می‌کند؛ صفر گزارش‌شده ناشی از اندازهٔ مشاهده‌شده است، نه صرفاً default initialDimension.

## نتیجه و حدود

اندازه‌گیری فرزند داخل پنل hidden یک مسیر مشخص در کد برای هشدار صفر/صفر است. شاهد مرورگر هم بعداً محورهای ماهانه/فصلی و فیلترها را نشان داد؛ بنابراین هشدار به‌تنهایی اثبات خالی‌ماندن دائمی همهٔ نمودارها نیست. اما این بررسی، هر یک از۲۳ هشدار را به یک container مشخص نسبت نمی‌دهد و علت کامل یا بی‌اثر بودن آن‌ها را اثبات نمی‌کند. بازچینی DOM و بخش‌های جمع‌شده نیز باید در بررسی هدفمند تفکیک شوند.

پیشنهاد اصلاح برای بازبینی مالک: شروع اندازه‌گیری chart تنها وقتی container واقعاً اندازهٔ مثبت دارد، با حفظ state کنترل‌ها و چهار پنل؛ یا mounting مرحله‌ای نمودار پس از نخستین نمایش و حفظ state بعدی. حذف warning، عدد ساختگی initialDimension و unmount کامل کنترل‌ها راه‌حل پذیرفته‌شده نیستند. پیش از تغییر، آزمون محدود باید نشان دهد container هشداردهنده hidden است و پس از نمایش اندازه/محور درست می‌شود؛ سپس یک رگرسیون state/filter/reload لازم است.

در این مرحله patch، Preview تازه یا ادعای رفع هشدار وجود ندارد. source checkout پاک باقی ماند.
