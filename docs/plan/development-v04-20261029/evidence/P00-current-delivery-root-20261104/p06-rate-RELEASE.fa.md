# اصلاح محدودیت درخواست‌ها: کد ادغام شد؛ نخستین انتشار پیش از ساخت رد شد

دستور تازهٔ مستقیم آرش، اصلاح نقص و انتشار پس از آزمون روی سرویس اصلی را مجاز کرد. root مالک انتشار و پذیرش است؛ C و همان مجریان موجود مالک مرور منبع و بستهٔ بودجه هستند. کارهای محصول نامرتبط، نصب SQL، فعال‌سازی پرچم بودجه و Hermes همچنان متوقف‌اند. برنامهٔ ۰٫۴ و ۸۵ تعهد آن تغییر نکرده‌اند.

## آنچه آماده و آزموده شد

[PR414](https://github.com/safariarash7777-source/portfolio-platform/pull/414) با منبع `73c4b3a` در `ad90bc2` ادغام شد. همهٔ تولیدکنندگان BRSAPI در همان رله از صف موجود عبور می‌کنند: حداقل ۳۰۰ میلی‌ثانیه پس از پاسخ/خطا، حداکثر ۳۰۰ شروع درخواست در پنجرهٔ لغزان پنج دقیقه، و سقف محلی ۲۰ شروع در ثانیه. کلید کالاییِ مصرف‌کنندهٔ کلید اصلی همان سقف مشترک را مصرف می‌کند؛ retry نیز دوباره از همین صف می‌گذرد. صف محدود، لغو پیش از ارسال، خطای ساعت و redirect بسته کنترل می‌شوند. فرایند تازه پنج دقیقه صبر می‌کند و در این فاصله دادهٔ ذخیره‌شده را می‌خواند و ارائه می‌دهد. تعویق محلی به‌عنوان خرابی شبکه یا گزارش مالی نامعتبر ثبت نمی‌شود.

[Linux واقعی ایزوله](p06-rate-linux-isolated-result.json) با تصویر Node موجود روی VPS، بدون شبکه و بدون mount دادهٔ اصلی اجرا شد: ۳۵۶ ورودی آزمون موفق و بدون skip؛ DB اصلی پیش و پس از اجرا سالم و کانتینر اختصاصی پاک شد. [تلاش اول](p06-rate-linux-first-empty-stdin-result.json) به علت stdin بسته، پیش از اجرای آزمون خارج شد؛ آن شکست محفوظ است. [CI دقیق منبع](https://github.com/safariarash7777-source/portfolio-platform/actions/runs/41879903533) هر پنج گیت را گذراند و آزمون TTY نیز در Linux اجرا شد. [مرور مستقل](p06-rate-independent-peer-REVIEW.fa.md) نقص P1/P2 پیدا نکرد. این‌ها پذیرش محصول روی مقصد محسوب نمی‌شوند.

## انتشار واقعی و مانع دقیق

[اجرای انتشار 41883223653](https://github.com/safariarash7777-source/portfolio-platform/actions/runs/41883223653) تنها یک بار از ناشر موجود اجرا شد. پیش‌پرواز زنده با exit صفر موفق بود، اما API لیارا پیش از build با HTTP400 نسخهٔ runtime را رد کرد: فقط latest/22/24 پذیرفته‌اند. `engines>=18` در CLI موجود ۹٫۵٫۱ به ۱۸ تبدیل می‌شود؛ `relay/liara.json` نسخهٔ صریح نداشت. [PR415](https://github.com/safariarash7777-source/portfolio-platform/pull/415) فقط نسخهٔ ۲۲ را در همان فایل صریح می‌کند؛ پورت، اپ، پلن، CLI و وابستگی‌ها ثابت‌اند. CI و مرور این اصلاح کوچک در جریان‌اند. هیچ نصب موفق یا پذیرش زنده‌ای از این تلاش ادعا نمی‌شود؛ بازخوانی current release پیش از تلاش تازه الزامی است.

## مرز شاهد و کار باز

[خواندن لیارا](p06-rate-liara-image-source-inventory.json) یک اپ در حساب، scale تنظیم‌شدهٔ ۱، کلید مشترک main/commodity و image جاری را نشان داد. image `apps/6a5351feb95bf1e50c1ee34f:12qvoyo45aeb` و source `29de2b84` با [سابقهٔ مستقل GitHub](p06-rate-prior-deployment-ledger.json) برابر بودند. این current-image reference است؛ اجرای موفق rollback یا پشتیبان بازیابی‌شدهٔ DB نیست. این صف محدودیت همهٔ تولیدکنندگان همین فرایند مدیریت‌شده را اعمال می‌کند؛ `globalEnforced=false` صریح باقی می‌ماند و مصرف‌کنندگان ناشناختهٔ خارج این استقرار تأیید نشده‌اند.

سه تحویل بعدی با مسئول روشن: root انتشار Node22 پس از CI/مرور و بازخوانی نسخه؛ root دو چرخهٔ طبیعی پیاپی دریافت→ذخیره→بازخوانی Production، بدون تحریک collector؛ C/root رفع جداگانهٔ baseline سهمیه و پوشش گزارش مالی با حفظ null و بدون SQL/reset خودکار. فروش/نرخ/مقدار و مسیر کامل عضو از صرف ادغام این اصلاح بسته نمی‌شوند.

گزارش وضعیت: **کد و آزمون Linux آماده؛ ادغام انجام‌شده؛ انتشار موفق و پذیرش مقصد هنوز انجام‌نشده**. هیچ هزینه یا میزبانی تازه ایجاد نشد.
