## اتصال‌هایی که باید جدا تطبیق داده شوند

- collector از SUPABASE_URL و service-role سرور استفاده می‌کند. کنترل‌پنل arsadata تطبیق literal آدرس تنظیم‌شده را نشان داده؛ تنظیم مؤثر process، هش کد اجراشده و DB پشت PostgREST هنوز اثبات نشده‌اند.
- build می‌تواند جفت NEXT_PUBLIC_LIARA را با next.config.js به NEXT_PUBLIC_SUPABASE نگاشت کند. این انتخاب build با تنظیم پنل یا محیط مؤثر فرایند یکسان فرض نمی‌شود.
- صندوق و بنیادی جفت اختیاری FUNDAMENTAL_READ دارند؛ اگر انتخاب شده باشد، خواندن ذخیره‌شده از همان جفت انجام می‌شود. مسیر legacy بازار می‌تواند fallback رله داشته باشد. تاریخچه و NAV تاریخی همچنان از جفت NEXT_PUBLIC_SUPABASE می‌خوانند. اختلاف بالقوهٔ اتصال، علت قطعی خطای سایت اعلام نشده است.
- getNavHistory در source فعلی در نبود تنظیمات یا شکست خواندن نیز آرایهٔ خالی می‌دهد؛ caller از شکل این بازگشت به‌تنهایی خطا را از تاریخچهٔ واقعاً خالی جدا نمی‌کند. این بدهی مستقل، در اصلاح محدود NAV collector دست‌کاری نشده است.

## سهمیه

قرارداد موجود lease برابر POST `/rest/v1/rpc/brsapi_budget_lease` با `p_day,p_want,p_hard` و قرارداد release برابر `/rest/v1/rpc/brsapi_budget_release` با `p_day,p_back` است. migration همان `sql/phase28_brsapi_budget.sql` است؛ تابع/DB تازه‌ای ساخته نشد.

شاهد قبلی، client خاموش، legacy enforcement خاموش و store ناسالم با HTTP404 را نشان می‌دهد. عدد ۰/۹۰۰۰ از حالت ابتدایی شمارندهٔ داخلی حاصل می‌شود؛ مصرف حساب تأمین‌کننده نیست. نبود توابع در VPS بررسی‌شده با 404 هنوز از طریق هویت فرایند/DB به هم متصل نشده‌اند. بازبین مستقل همچنین نبود GRANT صریح service_role در همین migration، validation ناقص بعضی فیلدهای پاسخ و نبود شناسهٔ idempotency/readback برای lease نامعلوم را ثبت کرد؛ ACL واقعی و علت 404 از source تنها نتیجه نمی‌شوند.

## قالب پاسخ لیارا

اجرای قبلی 41785607091 فقط رد در `framing_control` را ثابت کرده است. کد محلی پس از حذف حداکثر یک LF/CRLF، کنترل‌کاراکتر را رد می‌کند؛ محتوای فریم ثبت یا بازگشایی نشده است. نوع کاراکتر، ANSI، هدر Docker، موفقیت فرمان و PID/backend نامعلوم‌اند.

CLI نصب‌شده 9.5.1 و [کد رسمی shell](https://github.com/liara-cloud/cli/blob/master/src/commands/app/shell.ts) مسیر ترمینالی با START و اندازهٔ ترمینال، ورودی/resize و چاپ خام پیام را دارند. بسته‌شدن اتصال به exit0 می‌رود؛ این قرارداد رسید بسته و nonceدار نیست. در فرمان shell بررسی‌شده گزینهٔ صریح non-PTY یافت نشد؛ نبودن چنین API در کل سرویس ادعا نمی‌شود. صفحهٔ docs از ابزار وب قابل خواندن نبود؛ کد رسمی GitHub خوانده شد و CLI اجرا نشد.

گام بعدی امن: قرارداد رسمی non-PTY را مشخص کنند یا ابتدا تشخیص محدود نوع کنترل‌کاراکتر در همان اولین predicate برای بازبینی آماده شود. حذف ANSI، trim عمومی یا شل‌کردن parser راه‌حل پذیرفته نیست. این پیشنهاد مجوز retry زنده ندارد.
