# تطبیق آفلاین شواهد جست‌وجوی صندوق — ۴ نوامبر ۲۰۲۶

رسید اصلی receipt.json و تصاویر بدون تغییر می‌مانند. این پیوست، توصیف ناقص قبلی دربارهٔ نبود شاهد مقدار ورودی را اصلاح می‌کند؛ هیچ بارگذاری تازه‌ای انجام نشد.

- کنترل هدف دقیقاً `getByPlaceholder('نام یا نماد صندوق', {exact:true}).fill('اهرم')` بود؛ ورودی عمومی با placeholder «نماد یا نام صندوق — مثلاً وبملت یا طلا» هدف نبود.
- فایل production-selected.ax.txt، سطر۲۰۴۰ مقدار «اهرم» را برای text field جست‌وجوی صندوق ثبت کرده و سطر۲۰۴۴ تعداد «۹ نتیجه از۳۴۵» را نشان می‌دهد؛ سطر۲۲۸۱ همان کنترل متمرکز با مقدار «اهرم» است. پس اعمال فیلتر محلی و دریافت ورودی شاهد واقعی دارد.
- URL همان فایل، پارامتر compare را دارد ولی q ندارد. پس از reload نیز پنج انتخاب حفظ شده، ورودی جست‌وجو خالی و تعداد۳۴۵ شده است.
- در کد FundsFullBoard، onChange مستقیماً setSearch(e.target.value) را صدا می‌زند. useUrlBackedText ابتدا state محلی را تغییر می‌دهد و پس از۲۵۰میلی‌ثانیه router.replace را اجرا می‌کند؛ مقدار مؤثر URL هنگام set از window.location.search خوانده می‌شود.
- شاهد مستقلِ اجرای callback تایمر، پایان router.replace یا رسیدن q به URL پیش از reload وجود ندارد. در کد آزمون بین fill و reload، AX/evaluate/url/viewport/screenshot انجام شده ولی زمان‌بندی هر مرحله ثبت نشده است. این ترتیب جای انتظار صریح برای q را نمی‌گیرد.
- نتیجه: هدف صحیح و فیلتر محلی PASS محدود؛ ماندگاری جست‌وجو NOT_PASSED/علت نامعلوم؛ خطای قطعی محصول یا باگ React اثبات نشده. هیچ اصلاح محصول بر پایه این شکاف شاهد انجام نشد.
- ابزار مرورگر ثبت شبکه را ارائه نکرد؛ صفر بودن درخواست‌های تغییردهنده اندازه‌گیری نشده است. اقدام صریح تغییردهندهٔ داده انجام نشد.

برای پذیرش آینده، در سهمیه‌ای مستقل باید پیش از reload هم value و نتیجهٔ فیلتر و هم q در URL مشاهده شوند؛ سپس همان سه شاهد پس از reload مقایسه شوند. این یادداشت مجوز اجرای دوباره نیست.
