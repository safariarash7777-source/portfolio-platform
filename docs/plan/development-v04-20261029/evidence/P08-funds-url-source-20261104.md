# P08 — حفظ جست‌وجو و انتخاب صندوق در نشانی

این اصلاح روی main `636d38e7778fd58d8caf844c810d3d2bef2b1001` ادامهٔ صفحهٔ موجود صندوق‌هاست. صفحه، منبع داده، هویت صندوق، واحد و محاسبات مالی تغییر نمی‌کنند.

## مسئله و تغییر

در مشاهدهٔ واقعی ۴ نوامبر، فیلتر محلی «اهرم» ۹ نتیجه از ۳۴۵ صندوق داد؛ پنج انتخاب مقایسه حفظ شدند، اما `q` طی انتظار محدود دوثانیه‌ای وارد URL نشد. reload شرطی اجرا نشد. این شاهد علت خطای متناوب خواندن داده یا خرابی همهٔ منابع نیست.

در کد، نویسندهٔ جست‌وجو با تأخیر۲۵۰ms از `router.replace` استفاده می‌کرد؛ این ناوبری، صفحهٔ dynamic و خواندن‌های سرور را درگیر می‌کند. انتخاب صندوق نیز `history.state` داخلی Next را دوباره ارسال می‌کرد؛ در نسخهٔ نصب‌شده۱۵٫۵٫۲۸، وجود `__NA` باعث عبور از همگام‌سازی hookهای Next می‌شود.

- فقط در `/market/funds`، فیلتر و جست‌وجوی نمایشی از History API پشتیبانی‌شده با `replaceState(null, ...)` استفاده می‌کنند. مسیرهای دیگر همان ناوبری سرور را دارند.
- هر نوشتن، query فعلی مرورگر را همان لحظه ادغام می‌کند؛ `compare`، مرتب‌سازی، پارامترهای دیگر و hash حفظ می‌شوند. نویسندهٔ صفحهٔ قبلی نمی‌تواند مسیر تازه را تغییر دهد.
- Back/Forward، تایپ معوق را لغو و مقدار بازیابی‌شده را اعمال می‌کند؛ حتی اگر `q` بازیابی‌شده با مقدار قبلی برابر باشد.
- پل حساب صندوق به query فعلی کلاینت و همان اعتبارسنج موجود متصل است؛ نشانی ورود/ثبت‌نام پس از فیلتر، از نسخهٔ اولیهٔ سرور ساخته نمی‌شود. اطلاعات دسترسی همچنان از `getAccess` سرور می‌آیند.
- انتخاب پنج صندوق همان کنترل نوع/واحد و همان ذخیره در URL را دارد؛ نگهداری state خصوصی Next به خود router سپرده می‌شود.

این راهکار در [مستند رسمی Next از نسخه۱۴٫۱](https://nextjs.org/blog/next-14-1#windowhistorypushstate-and-windowhistoryreplacestate) پشتیبانی شده است. علت دقیق تأخیر مشاهده‌شده و خطای متناوب reader از این اصلاح به‌تنهایی قطعی نمی‌شود.

## نتیجه و مرز

۵۱ آزمون مرتبط شامل نوشتن هم‌زمان جست‌وجو/مقایسه، حفظ hash، لغو تایپ پس از Back، مسیر ورود، کیفیت/null و خواندن ناموفق گذشت. TypeScript و ESLint فایل‌های تغییرکرده موفق شدند. این‌ها آزمون Windows و اجرای کد با mock محدود هستند؛ مرورگر واقعی، CI Linux، Preview و Production باید با نسخهٔ دقیق جدا ثبت شوند.

تأخیر۲۵۰ms تایپ باقی است؛ بسته‌شدن یا reload پیش از پایان این مهلت تضمین ذخیرهٔ متن ندارد. این اصلاح ادعای تاریخ معتبر قیمت، طبقه واحد، بازده کامل، رفع reader دیتابیس یا پذیرش کل P08 نمی‌کند. هیچ دریافت provider، تغییر Auth، DDL یا نصب سرویس انجام نشده است.
