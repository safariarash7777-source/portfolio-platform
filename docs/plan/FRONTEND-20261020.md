## مبنا و مرز

مبنای تحویل `main@b44b6eb5be54e13fe1eb80293db25b8f0ddc941e` است؛ نسبت به کد بررسی‌شدهٔ `730623bd` فقط رسید COMMAND-CENTER افزوده شده است. هویت آرش، فارسی/RTL، فونت موجود، سرمه‌ای/طلایی و سه زبان بصری حفظ می‌شوند. ترتیب خانه معرفی آرش ← رسانهٔ واقعی ← بازار ← خدمات است؛ فضای عضو حول دارایی، بدهی و مدیریت ثروت پیش می‌رود. مرجع بصری، مجوز تغییر محاسبات یا تبدیل سایت به ترمینال عمومی معامله نیست.

انتخاب سراسری موجود خانه/بازار/رسانه از قرارداد فعلی `media_layout` می‌آید؛ query/hash/localStorage بازدیدکننده آن را عوض نمی‌کند. پیش‌نمایش مدیر از انتخاب ذخیره‌شده جدا می‌ماند. این برنامه ادعا نمی‌کند پوستهٔ عضو و مدیر اکنون به همان تنظیم متصل‌اند. توسعهٔ پوشش آن‌ها یک بستهٔ مستقل با آزمون و طراحی است؛ جدول تنظیمات یا کتابخانهٔ UI موازی ساخته نمی‌شود.

## قرارداد اجزا و حالت‌ها

| جزء/حالت | قرارداد فرانت‌اند | شاهد لازم |
|---|---|---|
| header، panel، action، badge | از typography و token موجود؛ سطح‌ها و عمق ملایم؛ label واقعی، focus واضح، اندازهٔ هدف داخلی حداقل۴۴px | render و keyboard contract؛ تصویر همان مصرف‌کننده در روشن/تیره |
| نمودار و جدول | واحد/منبع/دوره کنار عنوان؛ جدول یا فهرست قابل‌خواندن همان نقاط واقعی؛ بدون دادهٔ کافی نمودار ساخته نشود | مقایسهٔ دقیق داده/پنجره، zero/null، sparse و error؛ موبایل و صفحه‌کلید |
| loading | بیان دریافت همان بخش؛ skeleton جای تأیید داده یا مبلغ نیست | تأخیر واقعیِ کنترل‌شده؛ متن/فوکوس/اجزای سالم حفظ شوند |
| empty | فقط خواندن موفق و واقعاً خالی | fixture مستقل از شکست سرویس؛ هیچ «صفر ثروت» از فقدان رکورد ساخته نشود |
| error / stale / partial | خطا، تاریخ منبع و دامنهٔ پوشش روشن؛ retry فقط عمل موجود را انجام دهد | پاسخ دیررس/timeout و حفظ محتوای معتبر؛ error به empty تبدیل نشود |
| dirty / saving / unknown | پیش‌نویس حفظ؛ شناسه/بدنهٔ تلاش نامعلوم ثابت؛ هیچ resubmit خودکار | handler واقعی + transport قطع‌شده؛ readback مستقل و نسخه‌بندی در بستهٔ persistence |
| confirmed / preview | رسید معتبر مربوط به همان نسخه؛ preview ذخیره‌نشده برچسب دارد | reload و خواندن مستقل؛ نقش یا تأیید از وضعیت مرورگر ساخته نشود |

یک reducer یا hook مشترک فقط وقتی ساخته شود که دو گردش واقعاً قرارداد یکسان دارند؛ «unknown write» با «failed read» ادغام نمی‌شود. دادهٔ نسخه‌دار عضو و سوابق قدیمی در نمایش هم جدا می‌مانند. اجزای نمایشی نباید reader یا محاسبهٔ مالی موازی بسازند.

## گیت دسترس‌پذیری و تجربه

- صفحه‌کلید: ترتیب Tab منطقی در RTL؛ native button/link/form، نام قابل‌تمایز، focus قابل‌دیدن، Escape و بازگشت focus برای dialog، تب‌ها/بازشونده‌ها با state و رابطهٔ معتبر. کلیک را به div منتقل نکنید؛ تغییر hash نباید focus یا فیلتر را بی‌دلیل پاک کند.
- صفحه‌خوان: heading/landmark منظم؛ label و پیام خطا به input مربوط؛ وضعیت عملیات با `role=status` و خطای لازم با `role=alert`، بدون انتقال اجباری focus. `aria-busy` روی ناحیه‌ای نباشد که اعلان pending داخل آن تا پایان کار پنهان می‌شود. تست attribute به معنی آزمون واقعی فناوری کمکی نیست.
- موبایل/بزرگ‌نمایی: عرض‌های۳۲۰،۳۹۰،۷۶۸ و۱۲۸۰؛ reflow و متن در۲۰۰٪/۴۰۰٪؛ اسکرول افقی کل صفحه ممنوع. جدول/نمودار ضروری اگر دو بعدی است ظرف داخلی نام‌دار داشته باشد؛ تاریخ و مبلغ با `bdi`/جهت مناسب. همین matrix برای هر سه چیدمان در سطوحی که آن‌ها را پشتیبانی می‌کنند تکرار شود.
- خوانایی: کنتراست متن/کنترل اندازه‌گیری شود؛ معنا فقط با رنگ نباشد؛ tooltip جای label یا منبع نیست؛ کاهش حرکت رعایت و اطلاعات با خاموشی animation حذف نشود. میزان انطباق WCAG تا پایان ارزیابی مربوط، ادعا نشود.

راهنمای پایه: [W3C؛ پیام وضعیت](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) برای اعلان تغییر بدون جابه‌جایی focus، و [W3C؛ reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) برای خواندن هنگام کوچک‌شدن viewport/بزرگ‌نمایی. این‌ها معیار بررسی‌اند، نه رسید انطباق سایت.

## کارایی بدون پنهان‌کردن شکست

پیش از بهینه‌سازی، روی route و dataset مشخص اندازه‌گیری کنید: اندازهٔ JS، تصویر/فونت، زمان خواندن، LCP/INP/CLS و تعداد درخواست. cache/no-store خصوصی، گیت نشست و خواندن‌های محدودشدهٔ فعلی حفظ شوند. برای بهبود ظاهری، cron/بازخوانی provider یا prefetch همهٔ دادهٔ مالی اضافه نشود. heavy chart/editor فقط اگر اندازه‌گیری نشان داد لازم است با حفظ loading و دسترسی تدریجی بارگذاری شود؛ منبع مالی از client bundle عبور نکند.

هدف‌های تجربه برای دادهٔ میدانی، در صورت داشتن نمونهٔ کافی: LCP≤۲٫۵ثانیه، INP≤۲۰۰میلی‌ثانیه، CLS≤۰٫۱ در صدک۷۵؛ مطابق [Web Vitals](https://web.dev/articles/vitals). فعلاً این‌ها هدف‌اند و baseline عمومی این برنامه نیستند؛ تست آزمایشگاهی محدود را field/p75 نام ندهید. اتصال مقطعی backend از rendering جدا گزارش شود و budget reader، SLA کل صفحه نام نگیرد. سرویس تحلیلی پولی تازه لازم نیست.

FE-01 از [useTransition](https://react.dev/reference/react/useTransition) برای state همان transition استفاده می‌کند؛ pending نه رسید دریافت داده، نه deadline شبکه، نه شاهد موفقیت است. اگر refresh دوباره همان خطا را برگرداند، خطا باقی می‌ماند و اقدام دستی دوباره ممکن است.

## پذیرش و انتشار هر برش

۱. هدف، فایل مالک و «قبل/بعد» روشن؛ diff با main تازه و PR باز بررسی شود. آزمون رگرسیون باید رفتار واقعی component/handler را بسنجد؛ hook/transport seam و حدود آن ثبت شود.

۲. آزمون‌های مربوط، TypeScript، lint، اسکن سکرت و CI/build متناسب؛ نصب وابستگی یا تکرار build مشترک بدون علت انجام نشود. ورودی مصنوعی به دادهٔ واقعی یا تحلیل مالی برچسب نخورد.

۳. Preview با SHA دقیق: مسیر عمومی بی‌نشست، عضو/مدیر در گیت صحیح، هر حالت داده و تعامل مربوط. AX/HTTP موفق جای screenshot، کنتراست یا پذیرش بصری نیست. برای تغییر بصری، تصویر معتبر سه‌نما/موبایل و مقایسهٔ محتوا لازم است؛ در خرابی ابزار، همان گیت باز می‌ماند و اصلاح مستقل دیگر متوقف نمی‌شود.

۴. هماهنگ‌کننده پس از بازبینی، merge/Production/alias را جدا تأیید و همان تغییر را در مسیر واقعی بازخوانی کند. حساب ساختگی و دادهٔ متعلق فقط با هماهنگی؛ بازنشستگی نشست و حفظ سوابق در پذیرش مالی ثبت شود. برگشت این برش با revert مستقل ممکن است؛ migration یا دستکاری داده برای rollback فرانت‌اند انجام نمی‌شود.

این برنامه به‌تنهایی انتشار یا تکمیل کل فرانت‌اند نیست. وضعیت هر بسته، SHA و گیت باقی‌مانده در COMMAND-CENTER توسط root ثبت می‌شود؛ پیوند این برنامه در فهرست اسناد نیز با مالک همان فایل هماهنگ می‌شود.
